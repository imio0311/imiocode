# CH9 跨会话记忆系统 Checklist

> 每一项都通过运行代码、检查持久化结果或观察终端行为验证。自动化测试使用临时 userHome 和 workspace，不读写用户真实记忆与会话。

## 指令文件加载

- [ ] **AC1：用户与项目分层发现正确。** 用户目录、项目根目录、工作目录分别放置不同 `MEWCODE.md` 后启动新会话，首轮请求包含三份内容，顺序为用户到项目近端。（验证：指令集成测试捕获模型请求并断言内容及顺序）
- [ ] **AC1：非 Git 和缺失文件安全回退。** 在非 Git 临时目录启动以及逐个删除可选指令文件时，应用仍正常创建会话且不输出无意义错误。（验证：运行非 Git/缺失文件测试，观察退出码和问题列表）
- [ ] **AC2：合法 include 完整展开。** 相对路径、带单引号/双引号的含空格路径、多层引用和 UTF-8 中文内容按原位置展开。（验证：运行 include 参数化测试，对比完整展开文本）
- [ ] **AC2：include 安全边界生效。** 绝对路径、`..` 越界、符号链接逃逸、循环、深度 9 和超过 128 KiB 的来源被整体拒绝，提示包含来源和原因。（验证：运行安全边界测试并检查安全错误）
- [ ] **AC2：单来源失败正确隔离。** 一个项目指令引用失败时该来源不注入，其他用户/项目来源仍生效且没有半展开内容。（验证：捕获最终提醒快照）
- [ ] **AC3：只进入 messages 通道。** 连续两轮请求中指令位于 SESSION system-reminder，System Prompt 不含指令正文，工具 schema 和缓存意图未变化。（验证：Prompt 载荷集成测试）
- [ ] **AC3：提醒不污染可恢复历史。** 保存并恢复会话后，JSONL 和恢复消息中不含自动注入的指令提醒。（验证：搜索会话文件并断言恢复历史）

## 会话持久化与恢复

- [ ] **AC4：启动默认新建空会话。** 连续启动两次均生成不同当前会话标识，第二次不自动加载第一次历史。（验证：应用集成测试检查 current 和历史长度）
- [ ] **AC4：会话生命周期命令完整。** `/session current|list|new|resume <id>` 分别显示当前、列表、新身份和恢复结果。（验证：命令集成测试和真实终端操作）
- [ ] **AC4/AC11：删除必须确认。** `/session delete <id>` 在拒绝时文件和列表不变，接受时目标非当前会话消失；当前会话删除被拒绝并给出操作建议。（验证：确认 UI 两路径测试）
- [ ] **AC5：完整消息往返。** 含文本、三类思考元数据、工具调用、成功/失败工具结果、截断、耗时和退出码的会话保存恢复后逐字段一致。（验证：消息编解码与存储往返测试）
- [ ] **AC5：提交边界崩溃安全。** 分别截断 begin、message 和 commit，恢复结果只包含最后一个完整事务，不出现半轮用户或助手消息。（验证：事务截断参数化测试）
- [ ] **AC5：压缩历史可恢复。** 普通追加后执行手动或自动压缩，重启恢复得到压缩后的历史而非旧历史重复拼接。（验证：APPEND + REPLACE 集成测试）
- [ ] **AC6：尾部损坏可隔离恢复。** 最后一个有效提交后的损坏后缀被保存为 `*.corrupt-*`，主会话恢复到有效边界并显示警告。（验证：恢复测试检查两个文件和历史）
- [ ] **AC6：中部损坏安全拒绝。** 修改已提交的中部消息、摘要或工具链后恢复失败，原文件字节不变，当前会话标识和历史不变。（验证：损坏测试比较恢复前后哈希）
- [ ] **AC6：修复失败不覆盖原文件。** 模拟隔离副本或原子重写失败时，恢复被拒绝且主文件完整保留。（验证：注入文件系统失败的自动化测试）
- [ ] **N4：会话列表不加载正文。** 创建包含大量长消息的多个会话后执行 list，只读取头部和尾部元数据，不构造历史消息树。（验证：带计数探针的列表性能测试）
- [ ] **F11：保留策略可控。** 默认 0/0 不删除文件；配置天数或数量后只删除最旧非当前会话。（验证：固定时钟的保留策略测试）

## 双层长期记忆

- [ ] **AC7：双层记忆自动加载。** 用户与项目文件各含条目时，新会话请求依次包含用户、项目记忆，并明确项目冲突优先。（验证：捕获首轮 reminders）
- [ ] **AC7：稳定 ID 精确定位。** add 返回的 ID 可用于 edit 和 forget，编辑保持 ID 不变，删除不影响其他条目。（验证：记忆 CRUD 测试）
- [ ] **AC8：提取顺序严格。** 成功轮次的调用顺序为会话提交成功、模型提取、记忆原子更新、上下文刷新。（验证：协调器顺序探针测试）
- [ ] **AC8：新记忆下一轮生效。** 第一轮产生的合法偏好或项目事实在第二轮模型请求中出现，无需重启。（验证：两轮协调器集成测试）
- [ ] **AC8：提取失败不改判回复。** 模型错误、非法 XML/JSON 或记忆写入失败时，已流式展示的回复保持成功，只显示简洁警告。（验证：三种失败注入测试）
- [ ] **AC9：秘密和敏感内容不落盘。** 密钥、令牌、密码、凭据赋值、个人敏感信息、临时任务和大段原文均不写入两个 memory 文件，错误不回显秘密。（验证：安全样例测试并搜索临时目录输出）
- [ ] **AC9：重复与更新受控。** 相同规范化内容被跳过，`replacesId` 只更新同作用域条目，自动提取不能删除或跨作用域更新。（验证：候选合并测试）
- [ ] **AC9：记忆写入原子。** 模拟临时文件写入、刷新和移动失败，原 memories 文件仍可完整解析且无残留半条目。（验证：故障注入测试）
- [ ] **F9：容量限制一致。** 手动命令与自动候选都遵守条目数、单条字符数和文件字节数，越界时拒绝并说明类别化原因。（验证：边界值测试）

## 本地命令与 UI

- [ ] **AC10：`/session` 全部子命令可用。** 正常参数完成对应操作，缺失、额外或非法参数显示该子命令 usage。（验证：命令参数化测试）
- [ ] **AC10：`/memory` 全部子命令可用。** list 可选作用域，add/edit/forget 支持带引号正文和多余空白，非法作用域或 ID 显示准确错误。（验证：命令参数化测试）
- [ ] **AC10：本地命令不进入模型。** 全部已知、未知和语法错误的 `/` 输入都不增加 LLM 调用次数、不触发工具、不写入历史。（验证：假客户端计数集成测试）
- [ ] **AC11：运行中切换被拒绝。** 模拟 Agent active 时执行 new/resume/delete/历史替换，操作失败且当前会话不变；空闲后相同操作成功。（验证：并发状态测试）
- [ ] **AC11：通用确认默认安全。** y 接受，n/空输入/EOF/Ctrl+C/未知输入拒绝；权限 HITL 原有确认行为不变。（验证：JLine 输入序列测试和权限 UI 回归测试）
- [ ] **F12：反馈保持精简。** 正常保存和加载不打印正文；恢复、损坏隔离、记忆失败和配置错误能用不同简洁提示辨识。（验证：捕获 compact/verbose 两种 UI 输出）

## 配置、刷新与缓存稳定性

- [ ] **AC12：旧配置兼容。** 不含 `instructions/sessions/memory` 的现有配置按默认值启动。（验证：旧配置应用集成测试）
- [ ] **AC12：功能开关独立。** 分别关闭指令、会话或记忆后，仅目标功能停止；会话关闭时普通内存对话和自动记忆仍能工作。（验证：三组开关组合测试）
- [ ] **AC12：非法配置尽早失败。** 负数、必需项为零和超过硬上限的值在启动阶段报字段错误，配置与日志不要求或输出新秘密。（验证：YAML 参数化测试）
- [ ] **AC13：外部修改下一轮生效。** 修改、新建、删除顶层指令、include 依赖或 memories 文件后，下一轮请求使用最新有效快照。（验证：文件指纹刷新测试）
- [ ] **AC13/N4：无变化时不重复读取正文。** 连续多轮文件指纹不变时复用快照，只做一次轮次级元数据检查，不在 Agent 内部迭代重复扫描。（验证：文件访问计数探针）
- [ ] **N5：持久上下文文本稳定。** 文件未变化时多轮 SESSION reminders 字节完全相同，System Prompt 与 tools cache_control 保持现有值。（验证：两轮载荷快照对比）
- [ ] **AC13：正常退出只保存完整轮次。** 退出后全部成功提交可恢复，正在执行或取消的轮次不被伪造为成功提交。（验证：进程退出/取消集成测试）

## 安全、兼容与架构集成

- [ ] **N1：所有路径都在允许范围。** 指令 include、会话 ID、用户记忆和项目记忆分别不能逃离约定根目录，包含符号链接场景。（验证：跨模块路径安全测试）
- [ ] **N2：原始数据优先保留。** 所有会话修复和记忆写入故障场景都有原文件或隔离副本可追溯。（验证：故障测试比较字节和副本）
- [ ] **N3/AC14：跨平台路径样例一致。** Windows 盘符/反斜杠、Unix 根路径/正斜杠、不同换行符和 UTF-8 中文内容测试结果一致。（验证：平台无关路径与序列化参数化测试）
- [ ] **N7：测试不访问真实用户目录和模型。** 单元及集成测试全部注入临时 userHome/workspace 和假 LLM，测试结束后无真实 `~/.imiocode` 改动。（验证：测试配置审查和临时目录断言）
- [ ] **N8：既有功能无回归。** Agent、工具、权限、MCP、Plan Mode、上下文压缩、Prompt Cache 和精简 UI 的旧测试全部通过。（验证：运行完整测试套件）
- [ ] **架构依赖保持单向。** 核心对话模块不依赖 CH9 的 session/memory/persistence/runtime，底层服务不依赖 JLine 具体实现。（验证：编译依赖检查与 import 扫描）
- [ ] **共享 LLM 生命周期正确。** Agent、摘要和记忆提取串行复用客户端，应用退出只关闭一次；记忆提取请求看不到任何工具。（验证：生命周期假客户端测试）
- [ ] **本地隐私文件默认忽略。** `.imiocode/sessions/` 和 `.imiocode/memories.md` 被 Git 忽略，项目 `MEWCODE.md` 不被忽略。（验证：运行 `git check-ignore` 三组路径）

## 端到端场景

- [ ] **E2E-1：新会话恢复项目知识。** 在临时项目创建根/子目录 `MEWCODE.md`、include 文件和两层记忆，启动 ImioCode 并询问项目约定；回复体现全部上下文且近端项目规则优先。（验证：tmux 中真实请求与响应；tmux 不可用时记录原因并使用真实 Java 进程控制终端）
- [ ] **E2E-2：工具轮次跨进程恢复。** 请求 Agent 读取文件并回答，记录会话 ID，退出重启后执行 `/session resume <id>` 再追问上一轮文件；回复能延续历史，JSONL 含完整工具调用与结果。（验证：真实 Provider、真实工具和重启流程）
- [ ] **E2E-3：自动记忆跨会话生效。** 告诉 Agent 一个稳定偏好并成功完成一轮，确认 memory 文件生成；启动新会话后询问偏好，Agent 无需用户重复说明即可回答。（验证：真实提取请求、落盘文件和新会话回复）
- [ ] **E2E-4：手动管理与删除确认。** 实际执行 `/memory add/list/edit/forget` 和 `/session list/new/resume/delete`，分别走删除拒绝与接受路径，观察文件和列表变化符合命令结果。（验证：真实终端交互）
- [ ] **E2E-5：压缩后恢复。** 产生足够历史后执行 `/compact`，退出重启并恢复；压缩摘要保留关键上下文且旧消息未重复。（验证：终端压缩报告、JSONL REPLACE 和恢复追问）
- [ ] **E2E-6：损坏数据安全处理。** 备份会话后分别制造尾部与中部损坏；尾部出现隔离警告并恢复，中部拒绝且当前新会话可继续使用。（验证：真实文件修改、终端提示和文件哈希）
