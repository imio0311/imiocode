# CH9 跨会话记忆系统 Spec

## 背景

ImioCode 当前能够在一次运行期间维护对话和工具执行上下文，但进程退出后，历史会话、项目知识和用户偏好不会自动恢复。用户每次开始新会话时都需要重复说明项目约定与个人习惯，长时间使用时既浪费 Token，也容易出现前后行为不一致。

现有系统已经具备对话消息管理、上下文压缩、提示词分通道组装和本地配置能力。本章在这些能力之上增加跨会话持久化：项目指令和长期记忆在新会话中自动生效，完整对话可以按需恢复，同时保持提示词缓存、工具调用、权限检查和上下文压缩的既有行为不变。

## 目标

- 在每次新会话启动时，按明确优先级自动发现并加载用户级、项目级指令文件，将内容注入消息上下文。
- 支持安全的模块化指令引用，使大型项目约定可以拆分维护，同时防止越界读取、符号链接逃逸、循环引用和无限扩张。
- 将成功提交的完整对话以崩溃安全的 JSONL 格式持久化，并允许用户显式列出、恢复、新建和删除项目会话。
- 在每轮成功对话后，从交流内容中提取稳定的用户偏好、项目事实和长期决策，分别保存为用户级与项目级记忆，并在后续新会话中自动加载。
- 提供本地 `/session` 与 `/memory` 命令，让用户能够查看和管理会话、记忆；这些管理命令不发送给模型，也不污染对话历史。
- 将指令、会话和记忆相关开关与安全边界统一纳入 `config.yaml`，提供无需额外配置即可工作的安全默认值。
- 不改变当前 Agent Loop、权限系统、工具系统、上下文压缩和模型 Provider 的外部行为。

## 功能需求

- **F1：分层指令发现。** 每次新会话开始时，系统依次发现用户目录下的 `~/.imiocode/MEWCODE.md`，以及从当前项目 Git 根目录到工作目录路径上的各级 `MEWCODE.md`。更靠近当前工作目录的项目指令优先级更高；未处于 Git 仓库时，以当前工作目录作为项目范围。文件不存在时应静默跳过，不影响会话启动。
- **F2：安全的指令引用。** 指令文件支持使用独占一行的 `@include relative/path.md` 引入其他 Markdown 文件，含空格的路径可以使用引号。引用路径相对于当前指令文件解析；用户级引用不得离开用户配置目录，项目级引用不得离开项目范围，并且必须阻止绝对路径、`..` 越界、符号链接逃逸与循环引用。默认最大引用深度为 8，展开后的指令总量默认不得超过 128 KiB；违反限制时给出包含来源文件的明确错误。
- **F3：指令上下文注入。** 展开后的分层指令以会话级提醒消息注入消息通道，不拼接到 System Prompt，也不写入用户可恢复的对话历史。系统应保留来源与优先级信息，并明确后加载的高优先级项目指令可覆盖冲突的低优先级规则。
- **F4：项目会话生命周期。** 系统默认每次启动都创建新的空会话，不自动恢复旧对话。每个会话具有稳定标识、创建时间、更新时间、项目信息和当前状态；会话数据保存在当前项目的 `.imiocode/sessions/` 下。用户可以列出当前项目会话、查看当前会话、新建会话、按标识恢复会话以及删除会话；删除前必须获得明确确认。
- **F5：完整且崩溃安全的会话持久化。** 会话采用仅追加的 JSONL 格式保存。每轮只有在模型响应和工具结果成功提交到对话后才形成完整提交点，写入过程应确保异常退出不会把半轮内容识别为有效历史。持久化数据必须完整保留文本、思考内容、工具调用、工具结果、错误标记及恢复对话所需的元信息。
- **F6：会话完整性校验与损坏恢复。** 恢复会话时必须验证记录格式、提交边界、顺序关系和完整性信息。仅尾部损坏时，系统恢复到最后一个完整提交点，将损坏尾部隔离保存并向用户告警；中部损坏或消息链不合法时拒绝恢复，保留原文件且不得覆盖当前会话。
- **F7：双层长期记忆。** 用户偏好写入 `~/.imiocode/memories.md`，项目事实与长期决策写入 `<project>/.imiocode/memories.md`。两层记忆在新会话中自动加载并作为会话级提醒消息注入消息通道；冲突时项目级记忆优先。每条记忆具有稳定标识和可读内容，以便精确编辑和删除。
- **F8：自动记忆提取。** 每轮成功对话结束后，系统先持久化会话，再调用模型提取值得跨会话保留的信息。自动提取只允许保存稳定的用户偏好、可复用的项目事实和明确的长期决策；不得保存密钥、令牌、密码等秘密，个人敏感信息、临时任务状态或大段原始内容。重复或可更新的信息应合并而不是无限追加。提取、校验或写入失败只产生可见警告，不得把已成功的用户回复改判为失败。
- **F9：原子记忆更新。** 记忆文件更新必须通过临时文件和原子替换完成，避免崩溃造成原文件部分写入。自动提取与手动管理都必须遵守配置的条目数和内容大小限制；无效或越界内容应被拒绝并说明原因。
- **F10：本地会话与记忆命令。** 系统提供 `/session list|current|new|resume <id>|delete <id>`，以及 `/memory list [user|project]|add <scope> <content>|edit <scope> <id> <content>|forget <scope> <id>`。命令解析应支持必要的空白与引号处理，参数错误时显示针对该命令的用法。所有命令只在本地执行，不发送给模型、不触发 Agent Loop，也不写入对话历史；会话切换只能在没有运行中任务时发生。
- **F11：统一配置与安全默认值。** `config.yaml` 新增 `instructions`、`sessions`、`memory` 三组配置，至少覆盖功能开关、引用深度与总大小、会话保存与保留策略、自动记忆开关、记忆范围和容量限制。缺省配置应直接可用且采用保守边界；配置中不得要求保存模型密钥或其他秘密。关闭某项功能时，其余两项仍可独立工作。
- **F12：运行时集成与反馈。** 新会话建立或旧会话恢复后，后续每轮请求都应使用最新的指令和记忆上下文；记忆更新在下一轮即可生效。启动、恢复、隔离损坏数据、自动记忆失败和配置异常应通过简洁的 UI 状态或警告反馈，正常加载不应输出冗长内容。退出时应完成已提交数据的刷新，不等待或伪造尚未完成的模型轮次。

## 非功能需求

- **N1：安全性。** 所有来自指令引用、会话标识和本地命令的路径输入都必须经过规范化与范围校验，不能读取或写入约定范围外的文件。持久化内容和 UI 日志不得主动输出模型密钥、环境变量秘密或被安全规则识别出的敏感值。
- **N2：数据可靠性。** 会话提交和记忆更新在进程异常退出、磁盘写入中断或单条记录损坏后，不得破坏此前已经确认写入的有效数据。任何恢复或修复操作都应优先保留原始文件，并提供可追溯的隔离副本。
- **N3：兼容性。** 功能应支持项目当前运行环境，并在 Windows、Linux 和 macOS 的常见路径、换行符与 UTF-8 中文内容下保持一致行为。现有配置文件缺少新增配置段时必须继续正常启动。
- **N4：性能与容量。** 正常启动时，本地指令、记忆和会话元数据加载不应产生可感知的长时间阻塞；会话列表不得通过完整反序列化所有历史内容实现。注入模型的指令和记忆必须受可配置预算限制，避免无界占用上下文窗口。
- **N5：提示词稳定性。** 指令与记忆只进入消息通道，不改变稳定的 System Prompt 内容；没有文件或记忆变化时，同一会话各轮生成的持久上下文应保持确定顺序和稳定文本，避免无意义的 Prompt Cache 失效。
- **N6：可观测性。** 用户可以从简洁提示中区分会话保存、恢复成功、损坏隔离、记忆更新失败和配置错误。错误信息必须包含可操作原因，但不得泄露被过滤的敏感内容；正常成功路径不应增加冗长日志。
- **N7：可测试性。** 指令发现、引用边界、会话编解码、崩溃恢复、记忆过滤、命令解析与消息注入均应能够在不访问真实模型和用户真实主目录的情况下进行自动化测试；自动记忆的模型响应应可替换为确定性测试结果。
- **N8：既有行为兼容。** 未启用自动记忆或不存在历史数据时，Agent 的回复、工具调用、权限判断、Plan Mode、上下文压缩和退出流程应与本章改造前保持一致。旧项目无需创建指令或记忆文件即可继续使用。

## 不做的事

- 不引入向量数据库、Embedding、RAG、语义检索或基于相似度的记忆召回；本章只加载受容量限制的本地文本记忆。
- 不实现云端同步、跨设备同步、团队共享、多用户隔离或远程会话存储。
- 不提供会话分支、合并、导入、导出、搜索、重命名或跨项目恢复；会话管理仅限本项目列出、新建、查看当前、恢复和删除。
- 不实现会话自动恢复；每次进程启动仍创建新会话，旧会话必须由用户显式恢复。
- 不实现记忆版本历史、语义去重或复杂知识图谱；仅提供稳定标识、基础合并和手动增删改查。
- 不为每一条自动提取的记忆增加 HITL 确认；系统依靠严格白名单、敏感信息过滤、容量限制和手动管理命令控制风险。
- 不提供加密文件仓库或系统级密钥管理；敏感信息应在写入前被拒绝，而不是依赖落盘后加密。
- 不改变模型 Provider、工具协议、权限决策、上下文压缩算法或 System Prompt 七模块结构；仅使用它们已有的扩展入口完成集成。

## 验收标准

- **AC1（F1）：** 在用户目录、项目根目录和工作目录分别放置不同内容的 `MEWCODE.md` 后启动新会话，首轮模型请求能够获得全部内容，冲突规则以更靠近工作目录的内容为准；删除任意可选文件后仍可正常启动。
- **AC2（F2）：** 使用相对路径、带引号的含空格路径和多层 `@include` 时能够按顺序展开；分别尝试绝对路径、`..` 越界、符号链接逃逸、循环引用、超过 8 层和超过 128 KiB 的内容时，系统拒绝加载并显示来源与具体原因。
- **AC3（F3）：** 捕获同一会话连续两轮的模型请求，可以观察到展开后的指令位于消息通道且带有会话提醒边界，System Prompt 不包含这些内容，持久化的用户/助手消息中也没有复制该提醒。
- **AC4（F4）：** 启动程序后获得一个新的空会话；执行 `/session current`、`list`、`new` 和 `resume <id>` 能看到对应状态变化。执行 `delete <id>` 时必须先确认，拒绝确认后文件和列表保持不变。
- **AC5（F5）：** 完成一轮包含文本、思考、工具调用、工具结果和错误信息的真实对话后终止并恢复会话，恢复出的消息顺序与字段和终止前一致；模拟写入中途崩溃后，未形成提交点的半轮内容不会进入恢复历史。
- **AC6（F6）：** 人为破坏 JSONL 文件尾部后恢复，系统回到最后一个完整提交点、保留隔离副本并显示警告；破坏文件中部或构造非法消息链后，系统拒绝恢复、原文件保持不变、当前会话不被替换。
- **AC7（F7）：** 分别写入用户级和项目级记忆后新建会话，首轮模型请求包含两层记忆；制造冲突时项目级内容优先。每条记忆均可通过稳定标识被准确定位。
- **AC8（F8）：** 成功完成包含稳定偏好、项目事实和长期决策的对话后，会话先形成有效提交，随后相应记忆出现在正确作用域；下一轮请求立即包含新记忆。让提取模型或文件写入失败时，用户已收到的回复仍保持成功，只额外显示简洁警告。
- **AC9（F8、F9）：** 输入密钥、令牌、个人敏感信息、临时任务和大段原文时不会产生自动记忆；重复表达同一事实不会无限新增条目。模拟记忆更新中断后原文件仍可完整读取，越过条目数或大小限制的更新会被拒绝并说明原因。
- **AC10（F10）：** `/session` 与 `/memory` 的全部规定子命令都能在本地完成对应操作；带引号内容和多余空白能够正确解析，缺少或错误参数会显示精确用法。拦截模型请求和会话记录可确认这些命令没有进入 Agent Loop 或对话历史。
- **AC11（F10）：** Agent 正在执行任务时尝试切换或删除当前会话，操作会被安全拒绝；任务结束后可正常执行。删除会话的确认交互在接受和拒绝两条路径上均符合预期。
- **AC12（F11）：** 使用不含新增配置段的旧 `config.yaml` 能按安全默认值启动；分别关闭指令、会话或记忆功能后，目标功能停止而其他功能继续工作。配置非法范围时启动阶段给出清晰错误，配置文件不需要包含任何新秘密。
- **AC13（F12）：** 修改指令或记忆后，下一轮请求使用最新有效内容；启动、恢复、尾部隔离和自动记忆失败均有简洁可辨识反馈，正常加载不会逐条打印文件内容；正常退出后所有已提交轮次均可恢复，未完成轮次不会被伪造为成功。
- **AC14（N1—N8）：** 在 Windows、Linux 和 macOS 路径样例及 UTF-8 中文内容下运行自动化测试，路径范围、会话恢复和记忆读写结果一致；运行项目全部测试与端到端对话后，既有 Agent、工具、权限、Plan Mode、压缩和 Prompt Cache 行为无回归。
