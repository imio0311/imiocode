# CH10 Slash Command 内置命令框架 Spec

## 背景

CH9 已具备基础斜杠命令解析和部分本地命令，但注册、别名、列举、补全能力尚不完整，命令仍会直接依赖终端 UI，`clear`、`permission`、`status`、`review` 等常用操作也尚未统一接入。

CH10 将在现有框架上渐进式重构，形成完整、可扩展且行为确定的内置 Slash Command 系统。

## 目标

- 所有 `/` 输入先由命令系统处理，未知命令也不会误发给模型。
- `help`、`compact`、`clear`、`plan`、`do`、`session`、`memory`、`permission`、`status` 在本地执行。
- `/review [关注点]` 是唯一 Prompt 型例外：生成预设审查请求后进入 Agent Loop。
- 命令通过抽象 UI 能力操作界面，不依赖具体终端实现。
- 支持命令名与别名的 Tab 补全。
- 状态栏能反映 Agent 模式、权限模式和当前会话。
- 不改变 CH9 会话、记忆和持久化数据的既有语义。

## 功能需求

- F1：提供统一命令注册能力，支持规范命令名、别名、查找、稳定顺序列举和前缀补全；重复名称或别名冲突必须在启动时失败。
- F2：命令名大小写不敏感；参数支持多余空白、单/双引号和转义。未知命令、未闭合引号及参数错误均在本地显示错误，不进入模型。
- F3：命令只能依赖抽象 UI 操作和命令服务，不直接依赖具体终端实现。
- F4：命令结果分为三类：本地型直接返回文本；UI 型请求清屏、压缩、模式切换等确定性操作；Prompt 型生成用户请求交给 Agent，CH10 仅 `/review` 使用此类型。
- F5：提供十个核心内置命令：
  - `/help`：列出核心命令、用法和兼容命令。
  - `/compact`：手动压缩当前历史并显示 Token 变化。
  - `/clear`：只清空终端显示并重绘状态栏，不修改当前会话历史。
  - `/plan`：切换到只读规划模式。
  - `/do`：切回正常执行模式。
  - `/session`：保留 current、list、new、resume、delete 功能。
  - `/memory`：保留 list、add、edit、forget 功能。
  - `/permission`：无参数时显示当前模式和可用模式；带参数时只切换当前进程的权限模式。支持 `ask`、`auto-edit`、`read-only`、`full-access`、`lockdown`。
  - `/status`：显示 Provider、模型、工作目录、Agent 模式、权限模式、当前会话、近似上下文用量和 MCP 连接摘要，不显示密钥。
  - `/review [关注点]`：生成只审查、不修改代码的预设请求；附加参数作为审查重点，然后进入 Agent Loop。
- F6：所有 `/` 输入必须先经过命令系统。除 `/compact` 外的本地/UI 型核心命令不得调用模型、工具或写入对话历史；`/compact` 可以复用 CH8 的专用 LLM 摘要流程，但不得进入 Agent Loop 或执行工具；`/review` 是唯一明确进入 Agent Loop 的核心命令。
- F7：Tab 根据当前 `/` 前缀补全命令名和别名；单一候选直接补齐，多个候选显示稳定排序的菜单，不补全子命令参数。
- F8：状态栏随 Agent 状态、Plan/Do 模式、权限模式和会话切换及时更新；命令完成后回到可输入状态。
- F9：保留 `/exit`、`/quit`、`/verbose`、`/compact-ui` 的原有行为，作为兼容命令；在帮助中单独列出，也参与命令名补全。
- F10：本地命令的输出保持精简；执行失败不得导致交互循环退出，也不得泄露密钥、内部异常堆栈或敏感配置值。

## 非功能需求

- N1：保持 CH9 会话、记忆、压缩、Plan Mode、权限确认和精简 UI 行为兼容。
- N2：命令查找应为常数时间；命令列表与补全结果必须稳定、可预测。
- N3：命令执行期间遵守现有会话忙碌状态；不得在 Agent 正在运行时并发切换会话、清理历史或修改运行模式。
- N4：状态、帮助和错误输出不得包含 API Key、MCP Header、敏感环境变量或原始异常堆栈。
- N5：命令和 UI 通过接口解耦，命令模块不得依赖 JLine 等具体终端实现。
- N6：Windows、Linux 和 macOS 使用相同命令语法；引号、空格、中文和反斜杠参数行为一致。
- N7：Tab 补全不得读取模型、执行工具或扫描大型项目目录；正常输入过程不能产生明显延迟。
- N8：全部核心命令、兼容命令、解析错误和未知命令都必须有自动化测试。
- N9：端到端验收必须证明八个非压缩的本地/UI 型核心命令不增加模型请求次数；`/compact` 在需要压缩时只产生专用摘要请求且不执行工具；`/review` 恰好产生一次正常 Agent 请求。
- N10：新增能力不得降低现有全量测试覆盖，也不得修改或提交用户已有的 `claude.md` 和 `hello.txt`。

## 不做的事

- 不加载用户或项目自定义 Slash Command 文件。
- 不支持命令热加载、插件命令或 Skill 命令。
- 不根据项目内容动态生成命令 Prompt；`/review` 使用固定模板加可选关注点。
- 不为命令本身增加权限检查；权限系统仍只约束工具执行。
- 不补全子命令、会话 ID、记忆 ID、文件路径或权限参数。
- 不把 `/permission` 的临时切换写回 `config.yaml`。
- 不新增命令管道、重定向、命令组合或 Shell 语法。
- 不增加新的远程 API、MCP 协议能力或审计日志。
- 不移除 `/exit`、`/quit`、`/verbose`、`/compact-ui` 兼容命令。

## 验收标准

- AC1：注册十个核心命令及四个兼容命令后，可按主名和别名查找；重复名称或别名冲突会立即失败。
- AC2：大小写、空白、引号、中文和 Windows 路径均能正确解析；未知命令和语法错误不会进入 Agent。
- AC3：命令模块不引用具体终端实现；使用假 UI 即可独立测试全部命令。
- AC4：命令执行结果能明确区分本地输出、UI 操作和转交 Agent 的 Prompt。
- AC5：十个核心命令的正常路径、参数错误及功能关闭路径均有可观测结果。
- AC6：依次执行除 `/compact`、`/review` 外的八个核心命令，模型请求数、工具执行数和对话历史均不因命令本身增加；`/compact` 在需要压缩时只调用专用摘要流程，不进入 Agent Loop、不执行工具，并以替换事务保存压缩历史。
- AC7：执行 `/review` 时恰好产生一次 Agent 用户请求；预设审查规则和可选关注点均出现在请求中。
- AC8：执行 `/clear` 后终端内容被清空并重绘状态栏，但当前会话 ID、消息数量和后续上下文保持不变。
- AC9：`/permission` 能显示并切换五种现有权限模式；切换立即影响后续工具权限判断，重启后恢复配置文件模式。
- AC10：`/status` 输出完整运行摘要，但不包含 API Key、认证 Header 或敏感环境变量值。
- AC11：输入命令名前缀并按 Tab，单候选直接补齐，多候选稳定显示；普通文本和命令参数位置不触发命令补全。
- AC12：切换 Plan/Do、权限模式和会话后，状态栏立即显示新状态；命令完成后终端保持可输入。
- AC13：`/exit`、`/quit`、`/verbose`、`/compact-ui` 行为与 CH9 一致，并在帮助的兼容区及补全候选中可见。
- AC14：命令处理异常只显示安全错误，交互循环继续运行，下一条普通对话仍可成功执行。
- AC15：项目成功打包，CH10 定向测试及既有全量测试全部通过。
- AC16：真实终端端到端场景证明八个非压缩本地/UI 命令零模型调用、`/compact` 只走专用摘要流程、`/review` 单次进入 Agent、Tab 补全可用且状态栏更新正确。
