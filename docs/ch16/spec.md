# CH16 生产代码中文注释 Spec

> 状态：已完成（2026-08-12）

## 背景

项目现有 561 个生产 Java 文件、约 2.69 万行生产代码。部分核心类型已有 Javadoc，但整体覆盖不均，复杂流程、并发控制、安全边界和模块职责仍缺少中文说明。

## 目标

- 为生产代码补充清晰、准确的中文注释。
- 重点解释设计意图、类职责、公共接口、复杂流程及异常边界。
- 保留 Java、API、Agent、Mailbox、Worktree 等必要英文技术术语。
- 不改变任何运行行为、公开接口或配置格式。
- 不为简单赋值、普通 getter/setter 和一眼可懂的代码增加冗余注释。
- 测试代码原则上不补注释，除非测试场景本身非常复杂。

## 功能需求

- F1：为生产代码中的核心类和接口添加中文 Javadoc，说明其职责、使用场景以及与其他模块的关系。
- F2：为公共构造器和公共方法补充中文说明；参数、返回值、异常存在理解成本时，补充对应标签。
- F3：为复杂算法、Agent Loop、流式调度、持久化、并发同步和资源清理等流程添加中文行内注释。
- F4：明确记录权限判定、路径校验、命令执行、凭据脱敏、Mailbox 和 Worktree 等安全边界。
- F5：为依赖特定协议或 Provider 行为的实现添加原因说明，例如 OpenAI、Anthropic、DeepSeek 和 MCP 的格式差异。
- F6：保留已有正确注释；英文注释能够准确表达标准术语时可以保留，关键模块的说明以中文为主。
- F7：注释必须与实际代码一致，不描述尚未实现的能力，也不改变代码行为。
- F8：按照模块分批补充注释，每批完成后执行编译或相关测试，最终运行全量测试。

## 非功能需求

- N1：注释统一使用简体中文，技术名词、协议名、类名和命令保留原文。
- N2：遵循标准 Javadoc 格式，避免使用无法生成文档的非标准标签。
- N3：注释重点说明“为什么这样设计”和“有哪些约束”，避免逐行复述代码。
- N4：注释内容应简洁；通常类说明 1–3 段、方法说明 1–3 句。
- N5：不得修改公开 API、序列化结构、配置兼容性和终端输出。
- N6：不得引入新的编译警告、测试失败或代码格式问题。
- N7：对安全、并发和资源生命周期的描述必须与实际实现严格一致，无法确认的内容不写。
- N8：保留用户当前未提交的 `claude.md`、`.imiocode/` 和 `hello.txt`，不修改、不暂存。

## 不做的事

- 不给测试代码批量补充注释。
- 不要求每个字段、局部变量、getter、setter 或简单委托方法都有注释。
- 不进行功能开发、架构重构、方法改名或代码风格重写。
- 不把所有英文技术术语强行翻译成中文。
- 不生成与代码无关的教程式长篇注释。
- 不修改第三方依赖、生成文件、构建产物和 `.imiocode/` 运行数据。
- 不为追求注释数量而添加重复、显而易见或可能快速过时的说明。
- 不处理现存且与本次注释任务无关的代码问题。

## 验收标准

- AC1：561 个生产 Java 文件全部经过扫描和分类，核心类型均具有中文职责说明或被明确判定为无需补充。
- AC2：公共 API 中存在理解成本的方法具有中文用途说明；复杂参数、返回值和异常具有必要的 Javadoc 标签。
- AC3：Agent Loop、流式调度、配置加载、Provider、MCP、权限、安全路径、会话持久化、Worktree 和 Agent Team 等关键流程包含中文设计说明。
- AC4：并发控制、跨进程锁、原子写入、消息 ACK、资源停止和清理等非显然行为具有准确注释。
- AC5：简单数据载体、枚举、getter/setter 和直观委托方法没有被无意义注释淹没。
- AC6：注释不包含 `TODO`、`TBD`、占位说明或与实现矛盾的描述。
- AC7：生产代码行为与公开接口保持不变；对比改动时只出现注释或必要的空白格式调整。
- AC8：`mvn test` 全量通过，测试数量不低于改动前的 619 项，0 failure、0 error。
- AC9：`mvn -DskipTests package` 成功并生成可运行的 fat JAR。
- AC10：在 tmux 中启动 ImioCode，提交一次真实请求，确认应用能调用工具并生成回复。
- AC11：按照本章 `checklist.md` 逐项记录实际验证证据。
- AC12：用户原有的 `claude.md`、`.imiocode/` 和 `hello.txt` 未被修改或纳入提交。
