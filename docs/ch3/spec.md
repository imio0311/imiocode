# ImioCode 第三章：工具系统 Spec

## 背景

ImioCode 已经具备面向 OpenAI、Anthropic 和 DeepSeek 的流式多轮文本对话能力，但模型目前只能生成文字，不能读取项目、修改文件、执行命令或搜索代码。

本章为 ImioCode 增加一套与模型服务解耦的统一工具系统，使模型能够声明并调用工作区工具。工具定义、工具调用和工具结果使用统一的内部语义，再分别适配三种模型协议。

## 目标

- 提供统一的工具描述、执行和结果表达能力。
- 提供读取文件、写入文件、精确编辑文件、执行命令、查找文件和搜索文本六个核心工具。
- 集中注册、启用、禁用和导出工具定义。
- 正确还原流式响应中的工具调用及其 JSON 参数碎片。
- 串行执行首个模型响应中的工具调用，将结果回传模型，并展示一次最终回复。
- 在终端中清晰展示工具调用的等待、执行和完成状态。
- 对文件及搜索工具实施严格的工作区边界和敏感路径保护。
- 为后续的多轮 Agent 循环和权限确认流程保留扩展点。

## 功能需求

- F1：系统应提供统一且与模型服务无关的工具描述，包含名称、说明、输入约束和风险元信息。
- F2：工具应接收结构化参数，并返回统一结果；结果应包含成功或失败状态、输出、安全错误信息和截断状态。
- F3：工具通用能力应统一处理参数校验、异常转换、输出截断和执行耗时，工具异常不得直接导致程序退出。
- F4：系统启动时应注册并默认启用 ReadFile、WriteFile、EditFile、Bash、Glob 和 Grep 六个核心工具。
- F5：ReadFile 应读取工作区内的 UTF-8 文本文件，支持指定行范围，并为文件不存在、路径非法和范围无效提供可理解的错误。
- F6：WriteFile 应支持创建文件和完整覆盖文件；目标父目录必须已经存在，不得自动创建目录。
- F7：EditFile 应执行精确文本替换；旧文本仅出现一次时才能修改，出现零次或多次时必须失败且不修改文件。
- F8：Bash 应以工作区为当前目录执行系统命令；Windows 使用 PowerShell，Linux 和 macOS 使用 Bash；结果包含退出码、标准输出和标准错误。
- F9：Bash 应具有固定超时；超时或用户中断时，应终止活动命令及其相关进程。
- F10：Bash 应标记为高风险工具。系统仅保证命令从工作区启动，不承诺通过操作系统级隔离阻止其访问工作区外部。
- F11：Glob 应按模式搜索工作区文件，以稳定顺序返回结果，并限制最大结果数量。
- F12：Grep 应在工作区内递归执行正则搜索，返回路径、行号和匹配内容，并限制最大结果数量。
- F13：除 Bash 外，所有涉及路径的核心工具都应拒绝绝对路径、父目录跳转及通过符号链接逃逸工作区的访问。
- F14：文件读取、文件搜索、文本搜索和命令输出应使用固定的安全资源限制；超过限制时应及时停止或截断，并附带明确标记。
- F15：工具注册中心应支持注册、查询、启用和禁用工具；重复名称注册必须失败。
- F16：只有已启用工具才能向模型公开并执行；未知或已禁用工具应返回失败结果。
- F17：工具注册中心应将统一工具描述分别转换为 OpenAI、Anthropic 和 DeepSeek 所需的请求格式。
- F18：三个模型客户端应在请求中携带已启用工具，同时保留原有纯文本流式响应能力。
- F19：流式响应解析应识别工具调用标识、名称及 JSON 参数碎片，并按到达顺序完整拼接。
- F20：多个交错出现的工具调用应按调用标识或流式位置分别组装，不得混合参数。
- F21：流式响应完成后应校验工具调用；缺少名称、缺少标识或参数 JSON 无效时，应产生安全的协议错误而不是执行调用。
- F22：同一模型响应同时包含文本和工具调用时，两者都应保留；文本继续流式展示，工具调用按顺序进入待执行队列。
- F23：首个模型响应包含多个工具调用时，系统应按顺序串行执行；单个工具失败应产生失败结果，但不得阻止剩余工具执行。
- F24：所有工具结果都应与原调用正确关联，并在全部执行完成后通过一次后续请求回传给模型。
- F25：工具结果回传后的模型响应只用于生成最终文本；若再次请求工具，系统不得执行，并应明确说明本章的单轮工具限制。
- F26：只有完整的“用户请求、首次模型响应、工具结果、最终模型响应”轮次才能加入正式会话历史。
- F27：若工具已经产生副作用但后续模型请求失败，系统不得声称已经回滚；终端应明确说明工具已执行但回复未完成。
- F28：终端应按顺序展示工具名称、输入摘要、等待、运行、成功或失败及结果摘要；视觉装饰不得进入工具参数、工具结果或会话历史。
- F29：用户中断时，系统应停止待执行工具和活动命令，不再发起后续模型请求，也不直接进入下一次输入提示。
- F30：OpenAI、Anthropic 和 DeepSeek 应提供一致的工具描述、调用解析、结果回传和单轮执行行为。

## 非功能需求

- N1：应用自身不得把 API Key、认证请求头或受保护文件内容写入终端错误、日志、会话历史或工具结果，已知密钥必须统一脱敏。Bash 子进程不得继承常见敏感环境变量；在没有操作系统级沙箱的情况下，系统不承诺识别或拦截命令主动读取并输出的所有未知秘密。
- N2：文件与搜索工具应集中保护 `config.yaml`、`.env`、`.env.*` 和 `.git/**`；Glob 应省略这些路径，Grep 不得搜索其内容，读写及编辑工具不得访问或修改它们。
- N3：路径必须规范化并限制在工作区内；访问前应逐级拒绝符号链接和 Windows 重解析点，并在实际读写前再次校验。系统应防止常规路径跳转和链接逃逸，但不承诺抵御外部进程并发修改文件系统结构造成的竞态攻击。
- N4：文本文件、JSON 参数、工具结果、终端内容和 Unicode 文件名统一按 UTF-8 正确处理。
- N5：流式 JSON 参数碎片必须精确按序组装，不得重复、丢失或改写。
- N6：工具参数错误、工具执行错误、协议错误及模型服务错误不得以未处理异常终止程序。
- N7：单个模型服务的工具协议错误不得影响其他模型服务适配器或原有纯文本行为。
- N8：原有纯文本流式、多轮对话行为应保持向后兼容。
- N9：模型协议中的会话历史应保持一致，未完成的工具轮次不得污染正式历史。
- N10：多个工具的执行顺序、终端展示顺序、结果顺序和回传顺序应保持一致。
- N11：文件搜索结果应采用确定性排序，保证相同工作区和输入得到稳定结果。
- N12：终端状态应及时更新，避免高频全屏重绘，并保留已有的行内滚动体验。
- N13：ANSI 控制符、边框、状态文字和颜色标记不得混入工具参数、工具结果或模型上下文。
- N14：资源限制应在读取或执行前以及执行过程中实施，不得先无限制读取全部内容再截断。
- N15：超时、中断或退出后不得遗留仍运行的命令进程、输出读取任务或其他相关资源。
- N16：Bash 只执行模型提供的命令字符串，应用不得将文件内容、API Key 或内部参数拼接到命令中。
- N17：工具、注册中心、协议适配和会话编排应可独立测试，测试不得依赖真实 API Key、真实模型服务或用户文件。
- N18：路径逃逸、符号链接、敏感路径和资源限制应在临时工作区中自动化测试。
- N19：三种模型服务应共享同一工具行为契约，并分别覆盖请求格式和流式解析测试。
- N20：Glob 和 Grep 不应依赖系统预装的 `rg`、`grep` 等外部搜索命令。
- N21：不同操作系统的差异应限制在命令执行边界内，其他工具行为应保持一致。
- N22：本章不要求并发执行，但任一工具异常后注册中心和会话仍应处于可继续使用的状态。
- N23：项目应在 Java 21 环境中干净构建，并保持第二章已有测试全部通过。
- N24：架构应为下一章的 Agent 循环和权限确认保留扩展点，但不得提前实现这些功能。

## 不做的事

- 不实现多轮、递归式 Agent 循环；本章最多执行一轮工具调用。
- 不实现权限确认流程；仅保留工具风险等级等元信息。
- 不并发执行工具；多个工具调用按模型给出的顺序串行执行。
- 不提供配置文件或终端命令来动态启用、禁用工具。
- 不实现操作系统级沙箱。Bash 仅保证从工作区启动，不承诺阻止命令访问工作区外部或敏感文件。
- 不新增创建目录、删除、移动、复制等文件工具。
- 不处理二进制文件。
- EditFile 不提供模糊匹配、补丁应用或差异编辑。
- 不自动回滚工具产生的文件或命令副作用。
- 不执行自动 Git 提交。
- 不提供网络访问、网页搜索或远程服务工具。
- 不支持第三方工具插件和运行时动态发现。
- 不保存跨进程的工具调用记录。
- Bash 每次调用都是独立进程，不保持 Shell 会话状态。
- 不实现工具失败后的自动重试。
- 不提供复杂的 Markdown、代码差异或全屏工具结果界面。

## 验收标准

- AC1（F1–F3）：任一工具都能提供统一的名称、说明、输入约束和风险信息；执行后统一返回成功状态、输出、错误、耗时及截断状态，参数或执行异常不会导致程序退出。
- AC2（F4、F15–F16）：启动后六个核心工具默认可用；工具可通过注册中心启用或禁用；重复注册会失败；未知或已禁用工具不会执行，并返回明确结果。
- AC3（F17）：同一套工具定义能够分别转换成 OpenAI、Anthropic 和 DeepSeek 所需的请求格式，且只包含已启用工具。
- AC4（F5）：ReadFile 能读取工作区内的 UTF-8 文本文件及指定行范围；文件不存在、路径非法或范围无效时返回可理解的错误。
- AC5（F6）：WriteFile 能创建或完整覆盖文件；父目录不存在时失败，并且不会自动创建目录。
- AC6（F7）：EditFile 仅在旧文本恰好出现一次时完成替换；出现零次或多次时不修改文件并返回失败。
- AC7（F13）：ReadFile、WriteFile、EditFile、Glob 和 Grep 无法通过绝对路径、父目录跳转或符号链接访问工作区外部；无法读取、搜索或修改 `config.yaml`、`.env`、`.env.*` 和 `.git` 中的内容。
- AC8（F8、F10）：Bash 从工作区启动，Windows 使用 PowerShell，Linux 和 macOS 使用 Bash；结果包含退出码、标准输出和标准错误；界面将其标记为高风险工具。
- AC9（F9）：Bash 超时或被用户中断时，活动进程会被终止，不遗留继续运行的子进程，也不继续后续模型请求。
- AC10（F11）：Glob 能按模式搜索工作区文件，结果顺序稳定、数量受限，并自动排除受保护路径。
- AC11（F12）：Grep 能递归执行正则搜索，输出路径、行号和匹配内容，结果数量受限，并自动排除受保护路径。
- AC12（F14）：读取、搜索和命令输出超过固定安全限制时会及时停止或截断，并显示明确的截断标记，不会先无限读取再截断。
- AC13（F18）：三个模型服务的请求都能携带已启用工具，同时原有纯文本流式回复仍可正常工作。
- AC14（F19–F20）：将工具参数拆成多个流式 JSON 片段并与其他工具调用交错发送后，系统仍能按调用标识和顺序还原出完整且互不混淆的调用。
- AC15（F21）：工具调用缺少名称或标识、参数 JSON 不完整或格式错误时，系统返回安全且明确的协议错误，不执行错误调用，也不异常退出。
- AC16（F22）：同一模型响应同时包含文本和工具调用时，文本正常流式展示，工具调用完整保留并进入待执行队列。
- AC17（F23–F24）：首个模型响应包含多个工具时，系统按顺序串行执行；其中一个失败不阻止后续工具；所有结果均与原调用正确关联并一次性回传。
- AC18（F25）：工具结果回传后只允许模型生成一次最终响应；若该响应再次请求工具，系统不执行，并明确提示本章的单轮限制。
- AC19（F26–F27）：只有完整的“用户请求—首次响应—工具结果—最终响应”轮次进入正式会话历史；若工具已经产生副作用但最终响应失败，界面明确说明工具已执行、回复未完成，不声称已经回滚。
- AC20（F28）：终端按顺序展示工具名称、输入摘要、等待、运行、成功或失败及结果摘要；终端装饰内容不会混入工具参数、工具结果或会话历史。
- AC21（F29）：用户中断时，尚未执行的工具不会启动，活动命令被停止，不再请求模型，也不会直接进入下一次输入提示。
- AC22（F30）：相同的工具调用场景分别使用 OpenAI、Anthropic 和 DeepSeek 协议测试时，得到一致的解析、执行、结果回传及单轮限制行为。
- AC23：包含中文内容、中文文件名和 Unicode 参数的读取、编辑、搜索、结果回传及终端显示均保持正确。
- AC24：应用产生的错误、日志、终端内容、会话历史和普通工具结果中不出现当前配置的 API Key、认证请求头或受保护文件内容；Bash 子进程不继承常见敏感环境变量，已知密钥即使由命令输出也会被脱敏。
- AC25：原有纯文本、多轮对话和流式终端交互的现有测试全部继续通过。
- AC26：在真实终端端到端运行 ImioCode，输入一条需要读取或搜索项目代码的请求后，可以观察到工具调用过程、工具结果回传和最终回答；同一轮不会发生第二次工具执行。
- AC27：项目能够在 Java 21 环境中干净构建，全部自动化测试通过。
