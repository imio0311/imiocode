# 统一配置文件 Checklist

> 每一项都必须通过运行代码、测试或观察真实进程行为验证。先记录证据，再标记结果。

## 统一入口与默认值

- [x] C1：只保留根目录 `config.yaml` 时，Provider、Agent、上下文、MCP 和权限配置能够同时加载。（验证：运行统一加载集成测试，断言五个配置域及来源均正确。）
- [x] C2：`mcp` 与 `permissions` 均省略时，基础应用仍可启动，MCP 和权限按旧格式或安全默认值工作。（验证：在无旧文件临时目录加载最小配置，权限模式为 `ask`，MCP 为空。）
- [x] C3：`mcp: {}` 或空 `servers` 表示明确禁用 MCP，不读取任何旧 MCP Server。（验证：同时放置旧 MCP 文件，断言最终 Server 数量为 0、来源为 `UNIFIED`。）
- [x] C4：`permissions: {}` 表示统一权限接管并使用安全默认模式，不读取旧权限规则。（验证：同时放置旧 allow 规则，断言模式为 `ask` 且规则为空。）
- [x] C5：现有根级基础字段、Thinking、Agent、上下文和 Provider 默认值保持兼容。（验证：运行原 `ConfigLoaderTest` 全部用例。）

## MCP 统一配置

- [x] C6：统一配置中的 stdio Server 能完成配置解析、初始化握手和工具注册。（验证：使用本地可控 MCP 子进程运行集成测试，观察注册工具数大于 0。）
- [x] C7：统一配置中的 Streamable HTTP Server 能完成配置解析和连接。（验证：使用本地回环 HTTP 测试 Server，断言初始化和工具发现成功。）
- [x] C8：统一 MCP 域存在时，项目及用户旧 MCP 文件中的额外 Server 不会加载。（验证：新旧来源声明不同 Server，最终只包含新来源名称。）
- [x] C9：一个 MCP Server 的未知字段、类型错误、传输冲突、非法 URL 或缺失变量产生带 Server 名称的安全错误，不影响其他合法 Server。（验证：混合配置测试返回一个错误且合法 Server 仍存在。）
- [x] C10：旧格式 MCP 文件的现有合并顺序和禁用行为保持不变。（验证：运行旧格式优先级回归测试。）

## 权限统一配置

- [x] C11：统一权限配置支持五种现有模式，并保持每种模式的既有含义。（验证：参数化测试遍历全部模式。）
- [x] C12：统一规则按书写顺序匹配，分别产生 `allow`、`deny`、`ask`。（验证：同一工具准备重叠规则，断言第一条匹配生效。）
- [x] C13：工具名称和可选目标 Glob 匹配保持兼容。（验证：运行精确名称、通配符、目标匹配和不匹配测试。）
- [x] C14：统一权限域存在时，旧用户级、项目级和本地级权限规则均不参与决策。（验证：旧文件放置冲突 allow 规则，断言统一 deny/ask 结果不变。）
- [x] C15：非法模式、动作、空工具名或非法 Glob 阻止权限配置启动，不部分加载剩余规则。（验证：逐类输入无效配置，断言抛出可定位 `ConfigException`。）
- [x] C16：危险命令硬拦截和路径沙箱仍优先于统一配置中的 allow 规则。（验证：权限检查器回归测试中，危险命令与越界路径仍为 deny。）

## 旧格式回退与迁移

- [x] C17：根配置缺少 MCP 域时，现有旧 MCP 文件继续加载并产生一次 MCP 迁移提示。（验证：断言来源为 `LEGACY`，Server 等价，notice code 唯一。）
- [x] C18：根配置缺少权限域时，现有三层权限文件继续加载并产生一次权限迁移提示。（验证：断言来源为 `LEGACY`，模式与规则优先级等价。）
- [x] C19：根配置包含统一域但该域无效时直接报告错误，不回退旧文件。（验证：同时准备有效旧文件和无效统一配置，断言旧内容未生效。）
- [x] C20：迁移文档中的旧、新配置示例产生等价的 MCP Server 和权限决策。（验证：把两份示例分别送入加载器并比较规范化行为。）
- [x] C21：当前项目根配置已包含 Context7 与对应只读权限规则，当前项目不再依赖两份 `.local.yaml`。（验证：检查文件布局并运行统一加载探针，来源均为 `UNIFIED`。）
