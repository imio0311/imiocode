# 统一配置文件 Spec

## 背景

ImioCode 的基础模型、Provider、Thinking、Agent Loop 和上下文管理配置已经由项目根目录的 `config.yaml` 承载，但 MCP Server 与权限规则仍分别存放在 `.imiocode/mcp*.yaml` 和 `.imiocode/permissions*.yaml` 中。用户需要记忆多套文件名、结构和优先级，配置一次完整的 ImioCode 环境时容易漏项，也难以复制、审查和排错。

本次重构将项目根目录的 `config.yaml` 作为统一主配置入口，使一个文件能够描述当前已有的全部配置能力。同时保留旧配置文件作为兼容回退，避免已有用户升级后立即失效，并为后续移除旧格式提供清晰迁移路径。

## 目标

- 使用一份项目根目录 `config.yaml` 配置 Provider、模型、超时、Thinking、Agent、上下文、MCP Server 和权限系统。
- 启动时只需经过一个统一配置入口，即可得到各运行模块所需的有效配置。
- 当统一文件包含某一功能域时，以该功能域的统一配置为准，避免旧文件产生不可见的混合效果。
- 当统一文件缺少 MCP 或权限功能域时，继续按现有规则读取旧文件，保证向后兼容。
- 对配置结构、来源、覆盖关系和错误位置提供清晰反馈，方便用户排错。
- 允许敏感值通过环境变量提供或引用，示例和日志不暴露真实凭据。

## 功能需求

### F1：统一主配置入口

- 项目根目录 `config.yaml` 是项目配置的唯一主入口。
- 统一文件能够表达现有全部配置域：基础模型选择、Provider 连接、Thinking、Agent、上下文管理、MCP Server 和权限系统。
- 任一可选配置域缺失时使用现有默认值，不能要求用户为了启动而填写无关模块。
- 未启用 MCP 时允许省略 MCP 配置；未声明权限配置时继续使用现有安全默认模式。

### F2：MCP 配置归并

- 用户能够在统一文件中声明零个或多个 MCP Server，并配置启用状态、传输方式、启动命令或远程地址、参数、环境变量、请求头和超时。
- 统一文件存在 MCP 配置域时，该域作为完整的项目 MCP 配置来源，不再混入项目旧 MCP 文件或用户级 MCP 文件。
- 统一文件不存在 MCP 配置域时，继续按当前优先级和合并规则读取旧 MCP 配置文件。
- MCP 配置的安全校验、环境变量解析、传输限制和错误隔离行为保持不变。

### F3：权限配置归并

- 用户能够在统一文件中声明权限模式和有序权限规则。
- 每条规则继续支持允许、拒绝或询问决策，并可按工具名称和可选目标进行匹配。
- 统一文件存在权限配置域时，该域作为完整的项目权限配置来源，不再混入旧权限文件，规则顺序必须保持可预测。
- 统一文件不存在权限配置域时，继续按当前用户级、项目级和本地级规则加载方式运行。
- 未声明权限模式时使用现有安全默认值；危险命令硬拦截和路径沙箱不受配置归并影响。

### F4：兼容迁移

- 现有只包含基础配置的 `config.yaml` 无需修改即可继续启动。
- 现有 `.imiocode/mcp.local.yaml`、`.imiocode/mcp.yaml`、用户级 MCP 文件以及对应权限文件继续受支持。
- 旧文件仅在统一文件缺少对应功能域时生效，不能与已存在的统一功能域静默混合。
- 当使用旧配置回退时，启动信息应给出一次简洁迁移提示，指出建议迁移到 `config.yaml`，但不阻止启动。
- 迁移文档提供旧 MCP、旧权限配置到统一文件的等价示例。

### F5：环境变量与敏感值

- 现有环境变量覆盖行为保持兼容，环境变量仍可覆盖对应的基础配置值。
- Provider 密钥、MCP 环境变量和请求头中的敏感值支持通过环境变量引用，避免必须把明文凭据写进项目文件。
- 直接填写字符串的现有配置继续兼容，但文档示例只使用占位符或环境变量引用。
- 缺失被引用的必需环境变量时，启动错误应指出配置位置和变量名称，不输出其他敏感值。
- 配置对象、日志、终端错误和测试快照不得输出真实密钥、令牌或认证请求头。

### F6：统一解析、校验与错误报告

- `config.yaml` 每次启动只读取一次，解析后的内容由各模块共享，避免同一文件被多个加载器独立解析而产生不一致。
- 未知字段、错误类型、非法枚举、无效路径、错误 URL、冲突传输参数和非法权限规则必须在启动阶段被拒绝。
- 错误信息必须包含安全的配置路径，例如具体功能域、Server 名称或规则序号。
- 一个 MCP Server 配置错误仍按现有隔离策略处理，不应阻止其他合法 Server；基础配置或权限配置整体无效时应阻止不安全启动。
- 配置解析失败不得退回旧文件，以免用户修复统一配置前意外使用另一套设置。

### F7：示例与可观察性

- 项目提供一份覆盖所有配置域的 `config.yaml` 示例，且示例可以直接复制后按需删减。
- 启动时能够观察当前使用的是统一配置还是某个旧格式回退来源。
- 终端只显示配置来源、启用模块数量和安全摘要，不打印凭据或完整敏感配置。
- 项目启动说明、MCP 配置说明、权限模式说明和上下文配置说明统一指向 `config.yaml`。

## 非功能需求

### N1：安全

- 统一配置不得削弱危险命令检测、路径沙箱、MCP 环境隔离或 HITL 确认机制。
- 配置错误采用安全失败：不能确认权限语义时拒绝启动或拒绝相应模块。
- 敏感字段在内存对象的文本表示、异常和日志中保持脱敏。

### N2：兼容性

- 保持 Windows、Linux 和 macOS 的配置路径与命令表达能力。
- 保持 Anthropic、OpenAI、DeepSeek 及现有 stdio、Streamable HTTP MCP 行为。
- 旧格式回退至少覆盖当前已支持的全部旧文件与优先级行为。
- 不改变现有命令行交互、工具名称、权限模式含义和 Agent 行为。

### N3：一致性与可维护性

- 配置字段命名保持统一风格，同一概念不在不同功能域使用不同命名规则。
- 同一份配置只存在一个规范化结果，各运行模块不自行解释原始 YAML。
- 默认值和校验规则必须集中定义，避免统一入口与旧入口发生漂移。

### N4：可测试性

- 每个配置域、缺省行为、环境覆盖、旧格式回退、错误定位和脱敏均可独立测试。
- 至少覆盖一次包含 Provider、MCP、权限和上下文配置的真实进程启动场景。
- 原有测试继续保持 0 failures、0 errors。

## 不做的事

- 本次不立即删除或禁止旧 MCP、权限配置文件，只提供兼容回退和迁移提示。
- 不新增网络访问限制、资源配额、审计日志或新的权限模式。
- 不改变 MCP 协议能力，不增加 Resources、Prompts、Sampling 或 SSE。
- 不引入远程配置中心、数据库配置、热更新或运行中自动重载。
- 不实现多项目配置继承、YAML include 或任意表达式执行。
- 不自动修改用户目录中的旧配置文件，也不自动删除旧文件。
- 不把工具落盘结果、会话状态或自动记忆等运行数据放入 `config.yaml`。

## 验收标准

- AC1（F1）：只使用根目录 `config.yaml` 即可同时配置并启动 Provider、Agent、上下文、MCP 和权限模块。
- AC2（F1）：省略可选配置域时，应用使用现有默认值安全启动。
- AC3（F2）：统一文件中的 stdio 与 Streamable HTTP MCP Server 均能被发现、连接并注册工具。
- AC4（F2）：统一文件包含 MCP 配置域时，旧 MCP 文件中的额外 Server 不会被静默加载。
- AC5（F2、F6）：单个无效 MCP Server 产生带 Server 名称的安全错误，其他合法 Server 仍可连接。
- AC6（F3）：统一文件中的权限模式和有序规则能够分别产生 allow、deny、ask 的预期决策。
- AC7（F3）：统一权限配置生效时旧权限文件不参与决策，危险命令和沙箱仍优先拦截。
- AC8（F4）：现有不含 MCP、权限域的项目仍按原规则加载旧文件并成功启动。
- AC9（F4）：使用旧格式时终端显示一次迁移提示；配置正确时不改变现有运行结果。
- AC10（F4）：迁移文档中的旧、新示例产生等价的 MCP 注册和权限决策。
- AC11（F5）：环境变量能覆盖基础配置并能为 Provider、MCP 环境变量和请求头提供敏感值。
- AC12（F5）：缺少引用变量时错误只显示变量名和安全配置位置，日志与对象文本不包含真实凭据。
- AC13（F6）：统一文件只读取一次，各模块收到同一规范化配置结果。
- AC14（F6）：未知字段、错误类型、非法枚举和冲突配置在启动阶段产生可定位错误，且不会悄悄回退旧文件。
- AC15（F7）：完整示例涵盖全部配置域，相关启动和配置文档均指向根目录 `config.yaml`。
- AC16（F7）：启动摘要能区分统一配置与旧格式回退，并且不打印敏感值。
- AC17（N2）：三个 Provider、两种 MCP Transport、五种权限模式和 Plan/Do 行为通过回归测试。
- AC18（N4）：全部单元与集成测试 0 failures、0 errors，真实进程使用统一配置完成一次只读 MCP 工具调用和一次权限决策。
