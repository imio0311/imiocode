# ch8 上下文管理 Checklist

> 每项必须通过运行测试、检查文件或观察真实行为验证。先记录证据，再勾选结果。

## 1. 配置与预算

- [ ] 未配置 context 时使用 64,000 Token 窗口。（验证：加载仅包含旧字段的配置，断言窗口为 64,000）
- [ ] 未配置阈值时使用 0.80。（验证：加载默认配置，断言阈值为 0.80）
- [ ] YAML 能覆盖窗口和阈值。（验证：临时配置设为 16,000/0.70，观察加载结果）
- [ ] 环境变量优先于 YAML。（验证：YAML 与环境设置不同值，观察环境值生效）
- [ ] 非数字、零、负数和超过整数范围的窗口被拒绝。（验证：参数化配置加载测试）
- [ ] 阈值为 0、1、负数、NaN、Infinity 或非数字时被拒绝。（验证：参数化配置加载测试）
- [ ] 上下文窗口不大于模型输出上限时启动失败。（验证：窗口 4,096、输出 4,096 的配置测试）
- [ ] 旧 `config.yaml` 无需添加 context 字段即可启动。（验证：运行现有应用配置回归测试）

## 2. Token 近似估算

- [ ] 空白最小消息产生稳定正数估算。（验证：相同输入重复运行 100 次结果一致）
- [ ] 中文、英文、Emoji 和组合 Unicode 均能估算。（验证：多语言参数化测试无异常）
- [ ] Text、Thinking、ToolCall 和 ToolResult 内容全部计入。（验证：逐一增加内容块，估算严格增加）
- [ ] 工具调用 ID、名称和 JSON 参数计入估算。（验证：只扩大 arguments 后估算增加）
- [ ] ToolResult 的 output、error 和结果元信息计入估算。（验证：分别改变字段并比较）
- [ ] System Prompt、system-reminder 和工具 Schema 计入完整请求估算。（验证：对同一历史切换这些通道，估算相应增加）
- [ ] 输出 Token 上限作为预算预留计入。（验证：只提高输出上限，完整估算增加相同数量）
- [ ] 工具可见性变化会改变估算。（验证：Do 与 Plan/空工具集估算不同）
- [ ] 超大长度计算不会发生负数或整数溢出。（验证：构造边界计数，结果饱和为正长整数）
- [ ] 压缩前后报告使用同一算法，可从对应消息复算。（验证：管理结果断言 before/after 与独立估算一致）

## 3. 单个大工具结果落盘

- [ ] output+error 恰好 5,000 字符时不触发单结果落盘。（验证：边界测试）
- [ ] output+error 超过 5,000 字符时触发落盘。（验证：5,001 字符测试）
- [ ] UTF-8 文件包含该层收到的完整 output 和 error。（验证：使用中文与 Emoji 内容读回对比）
- [ ] 文件正文保留工具名、成功状态、截断标志、退出码和耗时。（验证：读回文件检查元信息）
- [ ] 对话占位包含预览、原字符数、相对路径和 read_file 提示。（验证：检查替换后的 ToolResult）
- [ ] 成功/失败、truncated、exitCode、duration 在占位结果中不变。（验证：前后对象字段比较）
- [ ] 成功结果占位位于 output，失败结果占位位于 error。（验证：两种结果测试）
- [ ] 相同结果重复管理不会创建第二个文件或嵌套占位。（验证：连续处理两次，目录文件数不变）
- [ ] 不同内容但相同调用 ID 不互相覆盖。（验证：生成两份结果，路径和正文都不同）
- [ ] 空、超长、含 `/`、反斜杠、`..` 和 Windows 保留名的调用 ID 不能逃逸。（验证：参数化恶意 ID 测试）
- [ ] 写盘失败时原 ToolResult 保持原样。（验证：注入只读/失败存储，比较对象）
- [ ] 工具自身已经截断的数据不会被上下文层伪装为完整恢复。（验证：truncated=true 仍保留标记与现有正文）

## 4. 累计旧结果瘦身

- [ ] 未落盘工具结果合计恰好 20,000 字符时不触发累计策略。（验证：边界测试）
- [ ] 合计超过 20,000 字符时优先处理最旧结果。（验证：检查被替换的调用顺序）
- [ ] 最近 3 条 TOOL 迭代保持完整。（验证：构造至少 6 个迭代，只允许更早结果落盘）
- [ ] 批量占位预览不超过 2,000 字符。（验证：检查占位长度）
- [ ] 一条 TOOL 消息包含多个结果时，每个结果独立判断且顺序不变。（验证：混合块测试）
- [ ] 单结果策略和累计策略在同次管理中不会重复写同一结果。（验证：目录文件数等于唯一落盘结果数）
- [ ] 第一层处理完全不调用 LLM。（验证：假 LLM 调用计数保持 0）
- [ ] 第一层处理后的估算不大于处理前。（验证：比较 ContextResult before/after）

## 5. 落盘路径安全

- [ ] 所有结果文件都位于当前工作区 `.imiocode/tool-results/`。（验证：解析真实路径并检查前缀）
- [ ] 工作区外绝对路径和 `..` 路径无法成为目标。（验证：恶意 ID/路径测试）
- [ ] `.imiocode` 是文件而非目录时安全失败且保留结果。（验证：临时工作区测试）
- [ ] `tool-results` 是文件、符号链接或 Junction 时安全失败。（验证：三种目标类型测试；无链接权限时记录 skip）
- [ ] 目标文件是链接、目录或其他非普通文件时不会被覆盖。（验证：预置恶意目标后执行）
- [ ] 正常文件通过同目录临时文件原子发布。（验证：监控最终文件完整且无残留临时文件）
- [ ] 相同内容的既有普通文件可幂等复用。（验证：再次写入不改变时间或文件数）
- [ ] 进程/写入异常不会留下被识别为完整结果的半文件。（验证：故障注入后检查目录）
- [ ] 落盘正文经过现有 SecretRedactor，不包含已注册秘密。（验证：注入 canary secret 并扫描文件）
- [ ] `.imiocode/tool-results/` 被 Git 忽略。（验证：`git check-ignore .imiocode/tool-results/check.txt`）
- [ ] Glob/WorkspaceWalker 不返回也不递归该目录。（验证：目录中创建文件后执行 glob）
- [ ] read_file 使用明确相对路径仍能读取结果文件。（验证：直接读取占位提供的路径）

## 6. 摘要请求与解析

- [ ] 摘要使用专用 System Prompt，不使用普通七模块 Prompt。（验证：捕获假 LLM ChatRequest）
- [ ] 摘要请求 tools 为空。（验证：组装 ApiPayload，工具定义数量为 0）
- [ ] 摘要请求不包含环境、Plan 或轮次 reminder。（验证：捕获 messages）
- [ ] 摘要请求不会触发 Agent Loop、权限或 MCP。（验证：相关监听器调用数为 0）
- [ ] prior_history 与 active_task 按事务边界分别序列化。（验证：检查 `<conversation_data>` 两个分区）
- [ ] 用户文本中的 XML 标签、`</summary>` 和控制字符串被转义。（验证：注入攻击样例不能改变结构）
- [ ] Text、Thinking、工具调用和结果按原顺序进入序列化文本。（验证：混合历史快照测试）
- [ ] 合法唯一 `<summary>`、`<prior_history>`、`<active_task>` 可解析。（验证：解析器成功测试）
- [ ] 根标签外文本、Markdown fence、重复/缺失/空标签被拒绝。（验证：参数化非法摘要测试）
- [ ] 超过摘要响应字符上限的内容被拒绝且不造成高内存放大。（验证：上限边界测试）
- [ ] LLM 返回 tool call、空文本或无合法标签时不替换历史。（验证：三种假响应）
- [ ] 摘要后估算不下降时不替换历史。（验证：返回超长合法摘要）
- [ ] 合法摘要重建为 USER 压缩消息和固定 ASSISTANT 确认。（验证：消息角色与数量）
- [ ] prior_history 版本不包含 active_task 内容。（验证：失败回写视图扫描 canary）
- [ ] 摘要正文不会通过普通聊天流式事件展示。（验证：TextDelta 监听器未收到摘要 canary）

## 7. 自动压缩与熔断

- [ ] 第一层处理后低于 80% 时不调用摘要 LLM。（验证：调用计数为 0）
- [ ] 第一层处理后达到 80% 时只调用一次摘要 LLM。（验证：调用计数为 1）
- [ ] AUTO 成功发出 Started 和 Completed 事件。（验证：事件顺序与前后 Token）
- [ ] 有结果落盘时发出 ResultsOffloaded，事件不包含正文。（验证：事件字段扫描）
- [ ] 摘要失败发出 Failed 并保留第一层结果。（验证：消息对象和落盘占位仍可用）
- [ ] 第 1、2 次摘要失败允许后续自动尝试。（验证：tracking 计数）
- [ ] 连续第 3 次失败打开 circuit 并发出 CircuitOpened。（验证：事件和状态）
- [ ] circuit 打开后继续执行第一层但不调用摘要 LLM。（验证：新大结果仍落盘，LLM 计数不变）
- [ ] 任意一次摘要成功清零连续失败状态。（验证：失败、成功、失败序列）
- [ ] 新 Agent 任务使用新的 tracking，不继承上一任务熔断。（验证：两个任务实例）
- [ ] 手动 `/compact` 不受自动任务熔断影响。（验证：circuit 后 FORCE 仍调用一次）
- [ ] 熔断且上下文仍无法安全发送时返回可恢复安全错误。（验证：错误类型和文案不含正文）

## 8. Agent Loop 与历史事务

- [ ] 每个模型迭代前都执行上下文管理。（验证：三迭代任务的管理调用次数为 3）
- [ ] 第一次迭代产生的压缩结果被第二次模型请求使用。（验证：第二次捕获的 messages）
- [ ] 工具结果在下一次迭代估算与落盘中可见。（验证：工具循环集成测试）
- [ ] 自动摘要后模型能继续调用工具并完成任务。（验证：假 LLM 多步场景）
- [ ] 正常完成时外层历史等于压缩后历史加完整当前轨迹。（验证：Session 快照）
- [ ] 压缩后任务失败时只回写 prior_history，不提交 active_task。（验证：canary 分区测试）
- [ ] 未发生压缩时现有“失败轮次不保存”语义保持不变。（验证：旧 ConversationSession 回归测试）
- [ ] stopped/cancelled/max-iterations 路径都携带最新可回写旧历史。（验证：终止原因参数化测试）
- [ ] summary 之后不存在孤立 ToolCall 或 ToolResult 协议块。（验证：三个 Provider 编码摘要历史）
- [ ] Plan Mode 的工具选择继续生效并影响预算，但摘要请求始终无工具。（验证：Plan 集成测试）
- [ ] pending system-reminder 不会被手动压缩消费或清空。（验证：压缩后下一轮仍收到 reminder）
- [ ] 压缩不改变当前 Plan/Do 模式。（验证：两个模式分别执行 `/compact`）

## 9. CONTEXT_LIMIT 恢复

- [ ] 三个 Provider 的已知输入超限错误映射为 CONTEXT_LIMIT。（验证：各 Provider 错误体测试）
- [ ] Provider 原始错误 message 不出现在安全异常文案。（验证：canary 扫描）
- [ ] OUTPUT_LIMIT 仍表示输出截断，不被误分为 CONTEXT_LIMIT。（验证：现有 max_tokens 场景）
- [ ] 未知 HTTP 400 不被宽泛识别为上下文超限。（验证：普通 bad_request 测试）
- [ ] CONTEXT_LIMIT 不走网络/限流的普通重试退避。（验证：LlmRetryPolicy 返回 empty）
- [ ] 首次 CONTEXT_LIMIT 触发一次 RECOVERY 摘要并重试原模型调用。（验证：调用序列）
- [ ] 恢复后的第二次 CONTEXT_LIMIT 直接返回，不再摘要。（验证：摘要调用总数为 1）
- [ ] 摘要请求自身 CONTEXT_LIMIT 不递归触发摘要。（验证：调用总数严格有界）
- [ ] 已经启动工具后发生错误时不进行上下文恢复重放。（验证：副作用保护场景）
- [ ] 取消或任务超时时，正在进行的摘要 LLM 请求被取消。（验证：阻塞假 LLM 在限定时间内结束）

## 13. 端到端场景

- [ ] 场景 A——大结果落盘：在真实 ImioCode 进程中让工具产生超过 5,000 字符输出，看到占位和文件路径，文件可由 read_file 取回。（验证：tmux 交互记录 + 文件内容）
- [ ] 场景 B——自动压缩：使用临时小窗口让多步任务达到 80%，看到自动压缩前后 Token，Agent 随后继续调用工具并完成。（验证：tmux 事件顺序与最终回复）
- [ ] 场景 C——手动压缩：完成至少两轮对话后输入 `/compact`，看到前后 Token，下一轮仍能引用压缩前的重要事实。（验证：tmux 对话记录）
- [ ] 场景 D——压缩失败：假 LLM 连续三次返回非法摘要，看到失败和熔断，无无限请求，原历史仍可继续使用。（验证：请求计数和后续回复）
