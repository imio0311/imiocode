# ch8 上下文管理 Spec

## 背景

ImioCode 已具备多轮 Agent Loop、工具调用、权限控制和 MCP 扩展能力，但当前会话历史只增不减。每轮模型调用都会携带已提交历史和当前任务轨迹；长时间工作后，大型工具输出、思考块和多轮对话会持续占用上下文窗口，最终导致请求被模型拒绝或 Agent 无法继续。

ch8 将在不依赖精确 tokenizer 的前提下，引入可配置的 Token 预算、工具大结果落盘、自动全量摘要和手动压缩入口，使 Agent 能在有限上下文窗口内持续工作，并把压缩后的历史可靠地交还给外层会话。

## 目标

- 在每次模型调用前近似估算完整请求的上下文占用，并预留模型输出空间。
- 优先用不调用 LLM 的方式缩减大型工具结果，再按需执行全量摘要。
- 当预计占用达到上下文窗口的 80% 时自动压缩，降低 `prompt_too_long` 风险。
- 允许用户通过 `/compact` 主动压缩，并看到压缩前后的 Token 变化。
- 压缩后保留任务目标、关键决策、文件状态、命令结果、错误和待办事项。
- 压缩失败时不破坏原始历史，不让 Agent 陷入反复压缩的死循环。
- 保持现有 Provider、Prompt Cache、Plan Mode、权限系统和 MCP 工具行为兼容。

## 功能需求

### F1：上下文预算

- 用户可以配置模型上下文窗口大小；未配置时使用 64,000 Token。
- 支持通过启动环境覆盖上下文窗口配置。
- 自动压缩阈值默认为窗口的 80%，并允许配置为大于 0 且小于 1 的比例。
- 预算判断必须为模型输出上限和固定请求内容保留空间，不能把整个窗口都分配给会话消息。
- 无效窗口或阈值配置必须在启动时明确报错。

### F2：近似 Token 估算

- 使用统一且确定性的近似算法估算上下文，不接入精确 tokenizer。
- 默认按 3.5 个字符约等于 1 Token 计算，并计入消息、内容块和 JSON 结构开销。
- 估算范围覆盖用户文本、助手文本、Thinking、工具调用名称与参数、工具结果输出与错误、摘要消息和提醒消息。
- 同一份输入必须得到相同估算结果；空值、Unicode、中文和超长内容不得导致异常或整数溢出。
- 压缩前后报告必须使用同一个估算器，保证变化可比较。

### F3：单个大工具结果落盘

- 工具结果的输出和错误合计超过 5,000 字符时，将本层收到的完整内容以 UTF-8 写入工作区内的 `.imiocode/tool-results/`。
- 文件名来源于安全化后的工具调用 ID；空 ID、路径分隔符、保留名和重名不能造成越界或覆盖。
- 对话中的原结果替换为短预览、原始字符数、保存路径和可用读取工具取回全文的提示。
- 成功状态、错误状态、截断标志、退出码和耗时等结果元信息保持不变。
- 已落盘的结果必须可识别且幂等处理，后续轮次不能重复写盘或生成嵌套占位文本。
- 写盘失败时保留原始结果并安全继续，不得因压缩造成内容丢失。
- “完整内容”指现有工具安全上限和脱敏链路处理后交给上下文层的完整结果；本章不突破工具自身的读取与输出上限。

### F4：旧工具结果批量瘦身

- 当所有工具结果的合计内容超过 20,000 字符时，对较旧结果执行落盘替换。
- 默认保留最近 3 个完整 Agent 迭代中的工具结果，优先瘦身更早的结果。
- 旧结果在对话中最多保留 2,000 字符预览；完整内容仍可从落盘路径读取。
- 单个大结果策略与批量策略可在同一次管理中组合，且同一结果最多写盘一次。
- 第一层管理不调用 LLM，执行后返回更新后的消息和新的 Token 估算。

### F5：自动全量摘要

- 第一层处理后，如果预计上下文仍达到可用预算的 80%，调用当前会话的 LLM 生成全量结构化摘要。
- 摘要请求不暴露任何工具，不能触发 Agent Loop、权限确认或 MCP 调用。
- 摘要输入覆盖压缩时的完整有效会话，提示模型输出且只输出一个 `<summary>` 块。
- 摘要至少保留：当前目标、用户要求、已完成工作、关键决策及理由、涉及文件、重要代码或标识符、工具与命令结果、错误与限制、未完成任务和明确下一步。
- 摘要成功后，将原有效会话重建为一条带有压缩标识的用户摘要消息和一条简短的助手确认消息。
- 重建后的会话必须满足现有消息角色约束，并能直接用于下一次普通模型调用。
- 如果摘要结果为空、缺少合法 `<summary>` 或压缩后反而更大，则视为失败并保留第一层结果。

### F6：手动 `/compact`

- `/compact` 是本地命令，不作为普通用户消息发送给 Agent。
- 用户触发后直接请求全量摘要，不因尚未达到自动阈值而跳过。
- 空会话或没有可压缩内容时不调用 LLM，并显示可理解的提示。
- 成功时显示压缩前 Token、压缩后 Token 和节省比例，并立即替换当前会话历史。
- 失败时显示安全错误，原会话历史保持不变，用户可以继续对话或稍后重试。
- 手动压缩不改变当前 Plan/Do 模式，也不清空待注入的会话提醒。

### F7：Agent Loop 与外层历史集成

- 每次 Agent 迭代调用模型之前执行上下文管理，而不仅在用户轮次开始时执行。
- 第一层无 LLM 管理每轮都可以执行；第二层仅在达到阈值、手动触发或需要从上下文超限错误恢复时执行。
- 压缩结果必须成为后续迭代使用的真实消息列表，不能只修改本轮临时副本。
- Agent 结束后，压缩后的已提交历史必须回写外层会话，再提交本轮新增且完整的轨迹。
- 如果压缩成功但本轮随后失败，外层会话仍保留成功压缩后的旧历史，但不提交未完成的本轮轨迹。
- 工具调用与工具结果在进入摘要前保持合法配对；摘要重建后不保留无法配对的协议内容块。

### F8：超限恢复与失败熔断

- Provider 明确返回上下文过长错误时，在没有执行过本轮强制摘要的前提下，允许强制摘要并重试一次。
- 自动摘要连续失败达到 3 次后，本次 Agent 任务内停止再次自动调用摘要 LLM，但仍执行第一层瘦身。
- 一次摘要成功后清零连续失败计数。
- 手动 `/compact` 不受先前 Agent 任务的自动失败计数影响。
- 熔断后若上下文仍无法安全发送，返回明确且可恢复的错误，不得循环消耗 API 请求。
- 取消、超时或关闭会话时，正在进行的摘要请求必须同步取消。

### F9：事件与终端展示

- 上下文层通过事件报告自动压缩开始、完成、失败和熔断，不直接依赖终端实现。
- 自动压缩完成时展示压缩前后 Token；失败时展示安全且不包含会话正文的原因。
- 手动 `/compact` 期间终端进入明确的压缩状态，完成后恢复 Ready，失败后仍允许继续输入。
- 工具结果落盘时可展示数量与目录，但不得在终端重复打印完整工具输出。
- 原始摘要提示和摘要生成正文不以流式聊天回复形式展示给用户。

### F10：落盘安全与生命周期

- 工具结果只能写入当前工作区 `.imiocode/tool-results/`，路径必须经过现有工作区安全策略校验。
- 目录或目标文件是符号链接、Junction 或其他重解析点时必须拒绝写入并保留原结果。
- 使用原子写入或等价策略，进程中断不能留下被当成完整结果读取的半文件。
- 落盘内容继续服从现有敏感信息脱敏规则。
- 工具结果文件默认跨轮次保留，确保摘要中的路径仍可读取；本章不自动清理旧文件。
- `.imiocode/tool-results/` 必须默认排除在 Git 提交之外，也应被 Glob 等常规项目扫描默认跳过。

## 非功能需求

### N1：安全与数据完整性

- 压缩和落盘均采用“成功后替换”语义；任一步失败都不能破坏仍可用的原历史。
- 摘要 LLM 输出视为不可信输入，必须验证边界和格式后才能替换会话。
- 日志、事件和错误信息不得包含完整历史、落盘全文或敏感凭据。

### N2：性能

- Token 估算和第一层瘦身对消息总字符数保持线性复杂度。
- 未达到阈值时不得额外调用 LLM。
- 已落盘结果的重复管理应保持低开销，不重复读取全文。

### N3：兼容性

- 同时支持 Anthropic、OpenAI、DeepSeek 三个现有 Provider。
- 未配置上下文功能时使用安全默认值，现有 `config.yaml` 无需修改即可启动。
- 不改变六个内置工具、MCP 工具、权限模式、Plan Mode 和 Prompt Cache 的既有外部行为。

### N4：可测试性

- Token 估算、阈值判断、落盘安全、占位结果、摘要解析、熔断和历史回写均可独立测试。
- 摘要测试使用可控的假 LLM，不依赖真实外部 API。
- 至少包含一个真实 ImioCode 进程的 `/compact` 与自动压缩端到端场景。
- 原有测试必须继续保持 0 failures、0 errors。

## 不做的事

- 不引入精确 tokenizer 或任何 Provider 专用分词依赖。
- 不使用机器学习自动选择压缩策略或动态训练阈值。
- 不实现跨进程会话恢复、会话数据库或自动记忆系统。
- 不实现多级递归摘要、向量检索、RAG 或语义搜索历史。
- 不自动清理 `.imiocode/tool-results/` 中的旧文件。
- 不突破现有工具输出上限来保存工具层已经截断掉的原始数据。
- 不压缩 System Prompt、工具 Schema 或 Provider 协议字段本身。
- 不让摘要请求调用工具、MCP、权限确认或 Agent Loop。

## 验收标准

- AC1（F1）：未配置时使用 64,000 Token 窗口和 80% 阈值；合法配置与环境覆盖生效，无效值阻止启动。
- AC2（F2）：同一混合消息历史重复估算结果一致，并覆盖中文、Thinking、工具调用参数和工具结果。
- AC3（F2）：包含超长内容时估算不溢出，压缩报告中的前后数值可复算。
- AC4（F3）：超过 5,000 字符的单个结果被写入安全目录，对话只保留预览、字符数、路径和读取提示。
- AC5（F3）：结果元信息不变；相同结果再次管理不会重复落盘。
- AC6（F3、F10）：空调用 ID、恶意 ID、重名、符号链接、Junction 和写入失败均不能越界、覆盖或丢失原结果。
- AC7（F4）：工具结果合计超过 20,000 字符时优先瘦身旧结果，并保留最近 3 个完整 Agent 迭代。
- AC8（F4）：第一层管理不产生 LLM 请求，处理后 Token 估算下降或保持不变。
- AC9（F5）：达到 80% 阈值时调用一次无工具摘要请求，并生成合法 `<summary>`。
- AC10（F5）：摘要后的两条消息包含压缩标识和关键上下文，可直接继续下一轮 Agent 工作。
- AC11（F5）：空摘要、非法标签或摘要膨胀时不替换可用历史。
- AC12（F6）：输入 `/compact` 不进入用户历史；成功后显示前后 Token 并替换历史。
- AC13（F6）：空历史不调用 LLM；手动压缩失败后历史不变且会话仍可使用。
- AC14（F7）：同一个多步 Agent 任务能在迭代之间使用压缩后的历史，并在任务结束后回写外层会话。
- AC15（F7）：压缩后本轮失败时，仅保留压缩后的旧历史，不提交未完成轨迹。
- AC16（F8）：上下文过长错误最多触发一次强制摘要重试，不形成无限请求循环。
- AC17（F8）：连续 3 次自动摘要失败后熔断；第一层仍执行，成功后计数重置。
- AC18（F8）：取消 Agent 时摘要请求被取消，任务在超时范围内结束。
- AC19（F9）：终端能观察自动/手动压缩的开始、完成和失败，且不打印摘要正文或完整落盘内容。
- AC20（F10）：落盘文件是 UTF-8 完整内容、原子生成、默认不进入 Git，也不被常规 Glob 扫描。
- AC21（N2）：未达到阈值的普通对话只做线性本地估算，不增加 LLM 调用次数。
- AC22（N3）：三个 Provider 的请求编码继续通过回归测试，Plan/Do、权限和 MCP 行为保持不变。
- AC23（N4）：全部单元和集成测试 0 failures、0 errors，并完成真实进程 `/compact` 与自动压缩端到端验收。
