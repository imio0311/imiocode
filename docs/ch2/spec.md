# 第二章：LLM API 与终端多轮对话 Spec

## 背景

ImioCode 是一个使用 Java 实现的终端 AI 编程助手。目前项目需要建立最基础的可运行交互闭环：用户在终端输入消息，ImioCode 调用选定的 LLM 厂商原生 API，并将模型回复实时展示在终端中。

本章需要支持 OpenAI、Anthropic 和 DeepSeek 三家厂商。不同厂商的请求格式、认证方式和流式响应协议存在差异，但这些差异不应影响用户的基本对话体验。

本章完成后，ImioCode 应具备继续开发工具调用、代码上下文管理和任务执行等后续能力的基础。

## 目标

- 建立从终端输入到 LLM 回复展示的完整运行链路。
- 支持 OpenAI、Anthropic 和 DeepSeek 的原生 API。
- 通过启动前配置选择当前使用的厂商、模型和认证信息。
- 在终端中增量展示模型生成的回复。
- 在当前运行周期内维护对话上下文，支持连续多轮交流。
- 对配置错误、认证失败、网络异常和响应中断提供可理解的终端提示。
- 为后续增加工具调用和更多模型厂商保留清晰的扩展边界。

## 功能需求

- F1: ImioCode 启动时必须从外部配置中读取当前使用的 LLM 厂商、模型名称、API Key，以及可选的 API 地址；不得要求用户在对话中输入认证信息。
- F2: ImioCode 必须分别支持 OpenAI、Anthropic 和 DeepSeek 的原生对话 API，并根据当前配置只调用选中的厂商。
- F3: ImioCode 启动成功后必须显示可识别的输入提示，接收用户输入，并将有效输入作为一条用户消息提交给当前 LLM。
- F4: 用户提交消息后，ImioCode 必须在终端中增量展示 LLM 返回的文本内容，而不是等待完整响应结束后一次性输出。
- F5: ImioCode 必须在当前运行周期内保存成功提交的用户消息和模型回复。后续请求必须携带此前的对话上下文，使模型能够延续对话。
- F6: 每轮回复结束后，ImioCode 必须重新进入可输入状态，允许用户继续发起下一轮对话。
- F7: 空输入或仅包含空白字符的输入不得触发 LLM API 请求，程序应继续等待有效输入。
- F8: 用户必须能够通过明确的退出指令或终端中断操作结束程序；程序退出时不得继续发起新的 LLM 请求。
- F9: 启动配置缺失或无效时，ImioCode 必须拒绝进入对话状态，并指出无效配置项，但不得显示完整 API Key。
- F10: 当 LLM API 返回认证失败、请求受限、模型不存在、服务端错误或无法识别的错误时，ImioCode 必须显示可理解的错误信息，并在可以继续运行时允许用户再次输入。
- F11: 当请求发生连接失败、超时或流式响应意外中断时，ImioCode 必须明确提示本轮未正常完成，不得将不完整的模型回复作为有效历史消息加入后续对话上下文。
- F12: 无论选择哪个受支持的厂商，终端中的输入、流式输出、多轮对话和错误提示行为必须保持一致。
- F13: ImioCode 必须按“环境变量 > 当前工作目录的 `config.yaml` > 内置默认值”合并启动配置。
- F14: `config.yaml` 必须支持按厂商分组保存 OpenAI、Anthropic 和 DeepSeek 的 API Key 与可选 Base URL，并支持配置当前厂商、模型、超时和最大输出 Token 数。
- F15: 环境变量只覆盖对应配置项；未被覆盖的配置继续使用 `config.yaml` 或内置默认值。
- F16: YAML 语法错误、字段类型错误、未知厂商或当前厂商必需配置缺失时，程序必须拒绝启动并指出配置位置，不得输出 API Key。
- F17: 仓库必须提供不含真实密钥的 `config.example.yaml`；实际 `config.yaml` 必须被版本控制忽略。
- F18: ImioCode 启动后必须显示启动面板，包含 ASCII Logo、产品名、版本号、当前厂商、模型和工作目录。
- F19: 启动面板必须显示当前运行状态，初始状态为 `Ready`。
- F20: 用户输入区域必须使用可识别的边框、输入标记和占位提示，与普通模型输出明显区分。
- F21: 输入区域必须支持多行编辑：`Enter` 提交，`Alt+Enter` 插入换行，并保留方向键、退格和输入历史能力。
- F22: 输入区域底部必须显示状态栏，左侧显示 `chat`，右侧显示当前模型名称。
- F23: 状态必须随请求过程在 `Ready`、`Thinking…`、`Streaming`、`Error` 之间变化，并在成功完成后恢复为 `Ready`。
- F24: 模型回复必须继续使用内联滚动方式展示；新回复不得覆盖启动面板、历史回复或当前输入内容。
- F25: 终端不支持 ANSI、颜色或 Unicode 边框时，界面必须自动降级为纯文本提示符，不能阻止对话。
- F26: 终端窗口宽度变化时，输入框、状态栏和文本不得相互覆盖；宽度不足时允许缩短装饰或换行显示。

## 非功能需求

- N1: 除模型自身响应时间外，ImioCode 在收到用户有效输入后应立即进入请求状态，不得因本地处理产生明显停顿。
- N2: 每个流式文本片段到达后应及时显示，正常情况下本地处理不应造成可感知的批量积压。
- N3: 终端输入和输出必须正确支持 UTF-8 内容，包括中文、英文、代码、常见符号和多行模型回复。
- N4: ImioCode 必须能够在项目明确支持的主流终端环境中运行；终端尺寸变化或不支持富文本能力时，基本输入和纯文本输出仍应可用。
- N5: API Key 不得出现在普通终端输出、错误详情、对话历史或默认日志中；错误信息如包含敏感认证内容，必须进行隐藏处理。
- N6: 一家厂商的协议差异或请求失败不得改变其他厂商的对话行为，也不得导致程序以未处理异常的形式退出。
- N7: 对话状态必须保持一致性。只有完整成功的模型回复才能加入历史；失败或中断的回复不得污染后续请求上下文。
- N8: 外部 API 调用、终端输入输出和对话状态应具有可独立验证的边界，以便使用模拟响应测试，不要求单元测试依赖真实 API Key。
- N9: 三家厂商的公共交互行为必须能够通过同一组行为测试进行验证，厂商协议差异通过各自的专项测试验证。
- N10: 在正常退出、请求失败或流式响应结束后，ImioCode 应及时释放网络连接及相关运行资源。
- N11: YAML 配置必须使用结构化解析库读取，不得使用字符串拆分等脆弱方式解析。
- N12: `config.yaml` 中的 API Key 不得出现在启动信息、异常、测试报告或配置对象字符串中。
- N13: UI 刷新不得导致模型回复重复、丢失或改变顺序。
- N14: 动态状态更新不得把 ANSI 控制字符写入对话历史或发送给 LLM。
- N15: UI 必须正确显示中文、英文、代码和多行输入。
- N16: UI 渲染逻辑必须与会话和厂商协议解耦，并可使用内存终端测试。
- N17: 不得通过持续高频全屏重绘实现内联界面。

## 不做的事

- 不保存或恢复跨进程的对话历史，退出 ImioCode 后本次会话内容随之清除。
- 不提供会话列表、会话切换、会话重命名或会话删除功能。
- 不支持在运行过程中切换 LLM 厂商、模型或 API 地址。
- 不支持 OpenAI、Anthropic、DeepSeek 之外的其他模型厂商。
- 不在某个厂商调用失败时自动切换到另一厂商。
- 不实现全屏 TUI、固定区域布局、鼠标交互或复杂的终端窗口管理。
- 不实现工具调用、文件读写、Shell 命令执行、代码修改或项目上下文收集。
- 不实现消息编辑、重新生成、自动重试、请求队列或并行对话。
- 不提供主动取消单次生成的专用交互命令；终端中断仅用于结束当前程序。
- 不展示 Token 用量、请求费用、模型内部推理内容或详细性能统计。
- 不实现完整的 Markdown 富文本渲染、语法高亮或代码块交互操作，模型文本以终端可读形式输出。
- 不提供代理配置管理、厂商账号管理或 API Key 的生成与保存功能。
- 不加密 `config.yaml` 内容。
- 不自动修改或回写用户的 `config.yaml`。
- 不搜索当前工作目录之外的配置文件。
- 不支持命令行参数指定其他配置文件路径。
- 不支持配置多个模型预设或运行时切换配置。
- 不实现全屏或 alternate-screen TUI。
- 不固定输入框在物理屏幕底部。
- 不实现鼠标操作。
- 不实现可配置主题或配色编辑器。
- 不实现 Markdown 富文本、代码语法高亮或图片显示。
- 不新增除 `chat` 之外的交互模式。
- 不为 UI 引入 Web、JavaFX 或 Swing。

## 验收标准

- AC1（覆盖 F1、F9）: 给定缺少厂商、模型名称或 API Key 的启动配置，当启动 ImioCode 时，程序拒绝进入对话状态，指出具体缺失或无效的配置项，且输出中不包含完整 API Key。
- AC2（覆盖 F1、F2）: 分别配置 OpenAI、Anthropic 和 DeepSeek 后启动 ImioCode，各次运行均只向选定厂商的原生 API 发起请求，并使用配置的模型名称、认证信息和可选 API 地址。
- AC3（覆盖 F3、F4、F6）: 启动配置有效时，终端显示输入提示；用户提交一条有效消息后，可以观察到模型文本随响应逐步出现；响应正常结束后，终端再次显示输入提示并接受下一条消息。
- AC4（覆盖 F5）: 用户先告知模型一个仅存在于本次会话中的信息，再在下一轮询问该信息，第二次请求包含此前完整的用户消息和模型回复，模型能够基于该上下文作答。
- AC5（覆盖 F7）: 用户连续提交空字符串或仅包含空白字符的内容时，不产生任何 LLM API 请求，程序保持可输入状态。
- AC6（覆盖 F8）: 用户输入约定的退出指令时，程序正常结束；用户执行终端中断操作时，程序停止当前活动并退出，不再发起后续请求。
- AC7（覆盖 F10）: 模拟认证失败、请求受限、模型不存在、服务端错误和未知 API 错误时，终端分别显示可理解且不泄露敏感信息的错误提示；对于可恢复错误，程序随后重新进入输入状态。
- AC8（覆盖 F11）: 模拟连接失败、请求超时或流式响应中途断开时，终端明确提示本轮响应未完成；用户再次发送消息时，后续请求历史中不包含该轮不完整的模型回复。
- AC9（覆盖 F12）: 对三个厂商分别执行相同的“启动、输入消息、观察流式回复、继续第二轮、退出”流程，终端表现和操作方式一致，不要求用户了解厂商协议差异。
- AC10（覆盖 F3、F4、F12）: 用户输入中文、英文或代码内容时，请求内容保持完整；模型返回中文、多行文本和代码片段时，终端输出不存在乱码或内容丢失。
- AC11（覆盖 F2、F10）: 任意一家厂商返回格式异常或调用失败时，错误被限制在当前请求内，程序不以未处理异常退出，也不影响使用其他厂商配置重新启动。
- AC12（覆盖 F4、F5、F11）: 模型完整流式响应结束后，该回复作为一条完整消息加入会话历史；响应未完整结束时，不加入有效历史。
- AC13（覆盖 F1-F12）: 在 tmux 中启动 ImioCode，使用任一已配置厂商完成至少两轮真实对话，可以观察到输入提示、流式回复、上下文延续和正常退出；随后对另外两家厂商执行等价的 API 连通与流式响应验证。
- AC14（覆盖 F1、F13、F15）: YAML 配置可独立提供启动所需配置；设置部分环境变量后，只有对应字段被覆盖，其余字段仍来自 YAML。
- AC15（覆盖 F13、F14）: 当前工作目录存在合法的分组式 `config.yaml` 时，三家厂商均能读取各自 API Key 和 Base URL。
- AC16（覆盖 F16）: YAML 语法错误、字段类型错误或缺少当前厂商 API Key 时，程序安全失败，错误指出配置位置且不包含 API Key。
- AC17（覆盖 F17）: 仓库包含无密钥的 `config.example.yaml`，并且真实 `config.yaml` 被版本控制忽略。
- AC18（覆盖 F18、F19）: 启动 ImioCode 后，首屏可观察到 Logo、产品名、版本、厂商、模型、当前目录和 `Ready` 状态。
- AC19（覆盖 F20、F22）: 输入区域具有明确边框和输入标记，底部左侧显示 `chat`，右侧显示当前模型。
- AC20（覆盖 F21）: 用户可以编辑一条多行消息，`Alt+Enter` 插入换行，`Enter` 只提交一次完整消息。
- AC21（覆盖 F23）: 模拟延迟流式响应时，状态按 `Ready → Thinking… → Streaming → Ready` 变化；失败时显示 `Error`。
- AC22（覆盖 F24）: 连续完成至少两轮对话后，启动面板、两轮用户输入和两轮模型回复均保留在终端滚动历史中，没有内容被覆盖。
- AC23（覆盖 F25）: 使用不支持 ANSI 的 dumb terminal 运行时，纯文本提示符、输入、流式回复和退出仍可用。
- AC24（覆盖 F26）: 在窄终端和调整窗口宽度后，输入框文字、状态栏和模型输出不重叠、不越界。
- AC25（覆盖 N13-N17）: 自动化测试确认状态更新不改变消息内容、流式片段顺序或发送给 LLM 的历史。
