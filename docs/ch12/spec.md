# CH12 Hook 系统 Spec

## 背景

ImioCode 已经具备多轮 Agent Loop、工具执行、权限确认、上下文压缩、跨会话记忆和 Skill 等能力，但格式化、工具调用前拦截、动态上下文补充等自动化仍需人工触发或写入核心流程。随着功能增加，把每种自动化直接耦合到 Agent、工具或 UI 会让主循环越来越难维护，也无法让用户通过配置扩展行为。

CH12 将提供统一的生命周期 Hook 系统。用户只需在项目根目录 `config.yaml` 的 `hooks:` 节点声明事件、条件和动作，即可在不修改 Java 代码的前提下挂载自动化逻辑。

## 目标

- 覆盖应用、会话、轮次、模型通信、工具、权限、压缩和错误等关键生命周期节点。
- 允许 Hook 根据当前上下文和条件选择性执行命令、注入提示、发送 HTTP 请求或声明未来的子 Agent 动作。
- 在工具真正执行前提供同步硬拦截能力，并把明确的拒绝原因反馈给模型，使模型能够调整后续策略。
- 提供可预测的运行时控制，包括单次执行、异步执行和命令超时，避免 Hook 阻塞或扰乱 Agent 主循环。
- 配置错误在启动阶段集中报告；运行期非拦截 Hook 的失败可观测但不破坏正常对话。

## 功能需求

- **F1：生命周期事件。** 系统必须提供以下 15 个稳定事件名：`startup`、`shutdown`、`session_start`、`session_end`、`turn_start`、`turn_end`、`pre_send`、`post_receive`、`pre_tool_use`、`post_tool_use`、`permission_request`、`compact`、`file_change`、`command_execute`、`error`。事件必须在对应操作的真实边界触发；没有发生的权限确认、文件修改或命令执行不得产生伪事件。
- **F2：统一 Hook 模型。** 每个 Hook 必须具有稳定标识、事件、可选条件、一个动作以及 `once`、`async`、失败策略等执行属性。运行时上下文必须能携带事件名、工具名、工具参数、文件路径、消息、错误和扩展数据。工具拦截必须使用专用拒绝错误表达拒绝原因，不能伪装成系统崩溃。
- **F3：条件表达式。** 条件必须支持字符串相等 `==`、不等 `!=`、正则匹配 `=~` 和 glob 匹配 `~=` 四种操作符，并支持用 `&&` 或 `||` 组合多个条件。单个表达式禁止混用两种连接符；组合条件按书写顺序求值并短路。条件字段至少支持 `event`、`tool`、`file_path`、`message`、`error` 和 `args.<参数路径>`。非法字段、操作符、正则、glob 或混合连接符必须在启动校验时报告。
- **F4：上下文变量替换。** 动作内容必须支持 `$EVENT`、`$TOOL_NAME`、`$FILE_PATH`、`$MESSAGE`、`$ERROR` 和 `$TOOL_ARGS.<参数路径>`。缺失的可选值替换为空字符串；替换只作用于声明为可模板化的动作字段，不得把变量内容再次作为模板递归展开。
- **F5：command 动作。** command 动作必须通过当前平台的 shell 在项目工作目录执行，向子进程显式传入 Hook 上下文环境变量，收集退出码、标准输出和标准错误。命令支持正数超时，默认 10 分钟；超时后必须终止其进程树并返回可识别的超时结果。同步命令输出可作为 Hook 输出供后续提示注入或拒绝原因使用。
- **F6：prompt、http 与 agent 动作。** prompt 动作必须将完成变量替换的文本作为 `system-reminder` 注入当前会话/轮次的 messages 通道，不修改 System Prompt。http 动作默认以 POST 和 JSON 发送；未配置请求体时序列化脱敏后的 Hook 上下文，支持模板化 URL、头和请求体，默认 10 秒超时，2xx 才视为成功。agent 动作在本章只保留合法配置和明确的“尚未实现”运行结果，不得悄悄启动主 Agent 或伪造成功。
- **F7：执行控制与失败策略。** `once` Hook 在进程内第一次实际调度后即标记为已触发，之后跳过；重启后标记重置。`async` Hook 在后台执行且不阻塞主流程，其完成或失败通过通知暴露。同步 Hook 支持 `ignore`、`fail` 和 `reject` 三种失败策略：非拦截事件默认隔离失败并继续主流程；`fail` 可使当前生命周期操作失败；`reject` 仅允许用于 `pre_tool_use`。`pre_tool_use` Hook 一律同步执行，禁止配置 `async`；带拒绝语义的动作不能异步执行。
- **F8：工具执行前拦截。** 每次工具调用在权限检查和工具实现执行前，必须串行运行匹配的 `pre_tool_use` Hook。Hook 显式拒绝或采用 `reject` 策略且执行失败时，工具不得执行，系统必须生成包含 Hook 标识和安全拒绝原因的工具失败结果回传给模型，让 Agent 可在下一轮调整方案。拒绝某个工具调用不能使整个 Agent 进程崩溃，也不能把它误报成权限拒绝。
- **F9：普通事件调度。** 除 `pre_tool_use` 外的事件统一通过非拦截调度入口运行。Hook 按配置出现顺序匹配和调度；本章不提供显式优先级。同步 prompt 输出按顺序收集，异步结果只进入通知队列。Hook 自身产生的失败不得递归触发新的 `error` Hook。
- **F10：Agent Loop 与应用集成。** 应用启动/关闭、会话创建/切换/结束、用户轮次、模型发送/接收、工具执行前后、真实权限询问、上下文压缩、文件成功变更、命令实际执行以及主流程错误都必须接入 Hook。prompt 输出必须在相应模型请求发出前进入可见上下文；工具后置 Hook 必须能读取工具执行结果摘要。应用关闭时必须停止或有界等待 Hook 后台任务，不能遗留非守护线程阻止退出。
- **F11：配置加载与校验。** Hook 仅从项目根目录 `config.yaml` 的 `hooks:` 节点按声明顺序加载。启动校验必须覆盖 Hook 标识唯一性、事件名、条件、动作类型、动作必填字段、超时、失败策略以及 `reject`/`async` 约束，并一次汇总多个错误。非法 Hook 配置必须安全降级为空 Hook 集并向终端报告脱敏错误，不能带着部分有效配置运行，也不能导致应用在进入 UI 前崩溃。
- **F12：可观测通知。** Hook 的同步/异步成功、跳过、失败、超时和工具拒绝必须形成脱敏通知；UI 在安全时机批量取走并展示简洁摘要。通知队列必须有容量边界，不能因长期会话无限增长；命令环境、HTTP 头和工具参数中的敏感值不得原样显示。

## 非功能需求

- **N1：安全性。** Hook 不得绕过既有工具权限系统去执行 ImioCode 工具；command 和 http 动作必须使用脱敏后的日志与通知，HTTP 仅允许 `http`/`https` 地址，并限制响应体读取大小。工具拒绝原因必须适合回传模型，不包含密钥、完整环境变量或内部堆栈。
- **N2：确定性。** 同步 Hook 必须按配置声明顺序执行；条件解析、变量替换、once 判定和通知顺序在相同输入下必须稳定。系统时钟、进程、HTTP 和后台执行能力应可替换，以便测试不依赖真实网络或随机等待。
- **N3：并发与生命周期安全。** once 判定在并发事件下必须原子化，确保同一 Hook 只调度一次。异步 Hook 不能阻塞 Agent 主线程；关闭后不得接受新任务，并应取消尚未开始的任务、终止仍在运行的命令或请求，在有界时间内释放资源。
- **N4：性能。** 未配置 Hook 时，各生命周期接入点应接近空操作，不产生进程、网络或额外模型调用。条件匹配和变量替换只能处理当前 Hook 集及当前上下文，不能扫描会话全历史；通知队列和动作输出必须有明确容量上限。
- **N5：兼容性。** 功能必须兼容 Java 21 和项目当前支持的 Windows、Linux、macOS 终端环境；command 动作应选择当前平台可用的 shell。现有未配置 `hooks` 的 `config.yaml`、Agent 行为、权限规则、会话文件和命令接口必须保持兼容。
- **N6：可诊断性。** 配置错误必须包含 Hook 标识或声明位置以及可操作原因；运行错误必须区分条件不匹配、once 跳过、退出码失败、超时、HTTP 错误、显式拒绝和未实现动作。对用户展示安全摘要，同时保留足够信息定位是哪一个 Hook 失败。
- **N7：可测试性。** 条件解析、模板替换、配置校验、各执行器、once/async、拦截反馈和 15 个生命周期事件均须有自动化测试；真实端到端验收至少覆盖 prompt 注入、格式化命令、危险工具拦截以及 Hook 失败不破坏后续对话。

## 不做的事

- 不持久化 `once` Hook 的已触发状态；应用重启后重新计算。
- 不提供 Hook 显式优先级或依赖图；同步执行顺序仅由 `config.yaml` 中的声明顺序决定。
- 不实现 agent 动作对应的真实子 Agent；本章只完成配置契约、占位执行结果和可观测提示。
- 不支持独立 `hooks.yaml`、用户级 Hook 文件、多层配置合并或运行时热重载；修改 `config.yaml` 后需要重启 ImioCode。
- 不增加 Hook 动作重试、退避、熔断、定时调度或持久任务队列。
- 不为已在本地 `config.yaml` 中显式声明的 Hook 动作增加逐次 HITL 确认；Hook 配置本身视为用户授权，但 Hook 不能调用或绕过 ImioCode 的内部工具权限链。
- 不提供 HTTP 流式响应、Webhook 服务端入口或 Hook 执行日志的永久审计存档。

## 验收标准

- **AC1（F1、F10）：** 使用事件记录 Hook 分别执行启动、关闭、创建与切换会话、正常对话、模型请求、工具调用、真实权限询问、手动或自动压缩、写文件、执行命令和错误场景，可观察到 15 个事件均在对应边界出现，且未发生的操作不会产生对应事件。
- **AC2（F2、F3）：** 为同一上下文配置四种比较操作符以及纯 `&&`、纯 `||` 条件，运行后只有匹配 Hook 被执行，并能观察到短路行为；配置混合连接符、非法字段、非法正则或非法 glob 时，启动输出同时列出所有错误且不加载任何 Hook。
- **AC3（F4）：** 在动作模板中使用全部六类变量和嵌套工具参数，执行后输出与 Hook 上下文逐项一致；缺失变量为空，变量值中再次出现 `$...` 时不会发生二次展开。
- **AC4（F5）：** command Hook 能在项目目录执行成功并获得上下文环境变量；失败命令能返回退出码和脱敏错误；超时命令会在配置期限内连同子进程被终止，应用仍可继续或按失败策略处理。
- **AC5（F6）：** prompt Hook 产生的文本以 `system-reminder` 出现在目标模型请求的 messages 中，不出现在 System Prompt，模型能依据注入内容回答；HTTP 测试服务能收到模板化 POST JSON，请求非 2xx、超时或过大响应时产生明确失败；agent 动作显示“本章尚未实现”且不启动 Agent。
- **AC6（F7、F9、F12）：** once Hook 在同一进程多次匹配时只调度一次，重启后可再次执行；异步 Hook 不延迟主流程并最终产生通知；多个同步 Hook 严格按配置顺序执行；成功、跳过、失败和超时通知可被 UI 一次取走且队列不会无限增长。
- **AC7（F8）：** 配置 `pre_tool_use` 拒绝写文件或命令工具后，目标工具没有产生副作用，模型收到带 Hook 标识和拒绝原因的 tool result，并能在下一轮选择替代方案；该拒绝不结束 Agent Loop，也不显示为权限拒绝。
- **AC8（F10）：** 文件成功写入或编辑后产生一次 `file_change`，实际启动 shell 命令时产生一次 `command_execute`，只有进入 HITL 时产生 `permission_request`；工具前后、发送前后和轮次前后的上下文数据能够正确对应同一次操作。
- **AC9（F11）：** 缺少 `hooks` 配置时现有应用正常启动且行为不变；合法 Hook 按 YAML 声明顺序加载；重复标识、未知事件、未知动作、缺少必填字段、非法超时、非 `pre_tool_use` 的 reject、异步 pre-tool 等错误被一次汇总、脱敏显示并整体降级为空 Hook 集。
- **AC10（N1–N6）：** Windows 与至少一种 Unix shell 的自动化测试均验证 shell 选择；并发触发 once 不会重复调度；关闭 Hook 系统后无后台线程阻止进程退出；未配置 Hook 时不产生进程、HTTP 或额外模型请求；日志和模型可见内容不包含测试密钥或完整堆栈。
- **AC11（N7）：** 项目编译通过，Hook 单元测试、集成测试及现有完整测试套件全部通过，且不改变既有配置、权限、会话和 Slash Command 行为。
- **AC12（端到端）：** 在真实 ImioCode 进程中依次验证四个场景：轮次 prompt 自动注入、文件修改后自动运行格式化命令、危险工具被 Hook 拦截后模型调整策略、一个失败的非拦截异步 Hook 只显示通知且下一轮对话仍正常完成。
