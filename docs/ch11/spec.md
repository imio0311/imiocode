# CH11 Skill 技能包系统 Spec

## 背景

IMIOCode 已具备工具调用、Agent Loop、权限控制、MCP、上下文管理、跨会话记忆和 Slash Command，但可复用工作流程仍需要写入 Java 代码或固定提示词。新增或修改流程需要重新编译，也无法按项目和用户灵活覆盖。本章把可复用操作封装为本地 Markdown Skill，让模型按需获取完整操作规程。

## 目标

- Skill 可直接编辑，无需重新编译应用。
- 启动阶段只向模型提供 Skill 名称和描述，需要时再加载完整内容。
- 同时支持 Slash Command 显式调用与自然语言自动匹配。
- 支持在主会话中执行和隔离执行两种模式。
- Skill 可限制工具、声明依赖，并携带参考资料和专属工具。
- 项目级 Skill 可覆盖用户级和内置 Skill，修改后可热加载。

## 功能需求

- F1：系统应解析带 YAML frontmatter 的 Markdown Skill；元信息与正文分离，缺失必填字段、名称非法或配置冲突时给出安全、可定位的错误。
- F2：系统应从项目级、用户级、内置级三个来源发现 Skill，并按“项目级 > 用户级 > 内置级”处理同名覆盖。
- F3：系统应支持单文件 Skill 和由 `SKILL.md`、可选 `tool.json`、可选 `references/` 组成的目录型 Skill。
- F4：Skill 目录内容发生变化后，无需重启或重新编译即可生效；正文执行时读取最新内容，目录元数据可自动检测或通过管理命令立即刷新。
- F5：每个有效 Skill 应自动成为同名 Slash Command，命令参数替换正文中的 `$ARGUMENTS`；Skill 删除或覆盖变化后命令目录同步更新。
- F6：Skill 支持 inline 和 fork 两种执行模式。inline 在主会话执行并保留完整结果；fork 在隔离上下文执行，仅把最终结果回传主会话。
- F7：fork 模式支持 full、recent、none 三档历史携带策略，默认 recent。
- F8：Skill 激活前应校验声明的工具依赖；任何依赖缺失、禁用或专属工具配置无效时立即失败，不启动模型执行。
- F9：Skill 激活后只能使用白名单内工具；多个激活 Skill 的白名单取并集，系统级 Skill 工具始终可见，以支持嵌套加载；Plan Mode 的只读限制仍具有更高优先级。
- F10：系统应提供模型可调用的 Skill 加载工具。模型根据启动阶段摘要识别意图后，可按名称加载完整操作规程并激活。
- F11：启动阶段注入的上下文只包含有效 Skill 的名称与描述，不包含正文、参考资料或专属工具定义；激活后完整内容在 Agent 后续每一轮重新注入，直到本次任务结束。
- F12：Agent 应维护本次任务的激活 Skill 列表，每轮重建环境上下文；多个 Skill 可同时激活，重复激活保持幂等。
- F13：目录型 Skill 的专属工具应由声明文件提供名称、描述、输入结构和命令模板；仅在 Skill 激活后注册和暴露，执行命令必须经过危险命令检测、权限规则、用户确认和工作区约束。
- F14：系统应提供 commit（inline）、review（fork）、test（inline）三个内置 Skill，分别完成规范提交、代码审查和测试诊断流程。
- F15：系统应提供 `/skill list`、`/skill info <name>`、`/skill reload` 管理入口，结果本地生成，不进入 Agent Loop。
- F16：Skill 加载和执行失败不得破坏当前会话、现有工具注册状态或上一份有效 Skill 目录。

## 非功能需求

- N1：启动摘要按名称稳定排序，只包含名称和描述，避免正文占用常驻 Token。
- N2：读取 Skill、参考资料和工具声明时限制在对应 Skill 根目录内，拒绝符号链接或相对路径逃逸。
- N3：Skill 名称、命令名称和工具名称应使用稳定、可移植的字符集；错误信息不得泄露密钥、环境变量值或完整异常栈。
- N4：热加载应采用完整快照替换；新快照校验失败时继续使用上一份有效快照。
- N5：现有 CH2—CH10 功能和会话持久化格式保持兼容。
- N6：内置 Skill 与用户自定义 Skill 使用同一解析、校验和执行规则。

## 不做的事

- 不实现 Skill 市场、在线检索、URL 安装或发布流程。
- 不实现 Skill 版本解析、依赖版本求解和自动升级。
- 不实现向量检索或基于语义向量的 Skill 匹配。
- 不允许 Skill 绕过现有权限系统、路径沙箱或危险命令硬拦截。

## 验收标准

- AC1：给定有效和无效 Markdown 示例，能够观察到正确解析结果或明确校验错误。（覆盖 F1）
- AC2：三个来源存在同名 Skill 时只暴露项目级版本；删除项目级版本并刷新后自动回退用户级版本。（覆盖 F2、F4）
- AC3：单文件和目录型 Skill 均可发现；目录型 Skill 激活后能读取参考资料并注册专属工具。（覆盖 F3、F13）
- AC4：修改正文后再次执行可看到新内容；修改元信息后执行 reload 可看到新摘要与命令。（覆盖 F4、F5）
- AC5：`/commit abc` 激活 commit Skill，正文中的 `$ARGUMENTS` 被替换为 `abc`，并在主会话留下结果。（覆盖 F5、F6）
- AC6：review fork 执行时主会话不保存子 Agent 的中间工具轨迹，只保存请求和最终结果；三档历史策略均有测试证据。（覆盖 F6、F7）
- AC7：声明不存在或禁用工具的 Skill 在模型调用前失败；未进入允许列表的普通工具不可见也不可执行。（覆盖 F8、F9）
- AC8：未激活时 API 工具清单只包含系统加载工具而不包含目录专属工具；激活后完整 SOP 和专属工具出现。（覆盖 F10、F11、F13）
- AC9：同一任务嵌套激活两个 Skill 后，两份完整指令每轮都存在，系统加载工具仍可继续调用。（覆盖 F9、F12）
- AC10：commit、review、test 三个内置 Skill 可被列出、查看并分别按规定模式调用。（覆盖 F14）
- AC11：`/skill list/info/reload` 均在本地立即返回且不消耗模型请求。（覆盖 F15）
- AC12：加载损坏 Skill 时应用不崩溃、会话不丢失、旧目录快照继续可用且输出安全错误。（覆盖 F16、N3、N4）
- AC13：全部单元测试、集成测试和真实终端端到端场景通过，既有功能无回归。（覆盖 N5、N6）
