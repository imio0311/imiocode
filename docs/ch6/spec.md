# ch6 权限系统 Spec

## 背景

imioCode 已具备多轮 Agent Loop 和文件、搜索、命令工具，但目前工具调用一旦被模型生成，就会直接进入执行流程。现有工作区路径约束只能提供部分保护，缺少统一的危险命令拦截、分层规则、权限模式和用户确认机制。

因此，模型可能在用户没有明确授权时修改文件或执行命令，也无法根据不同项目和使用场景调整信任等级。

## 目标

- 在所有工具执行前经过统一的权限决策流程。
- 对系统级破坏、整个项目的不可逆清理和沙箱逃逸进行无条件硬拦截。
- 支持用户级、项目级、本地级三层权限规则。
- 提供五种由低到高的权限模式，默认使用 `ASK`。
- 对需要人工判断的操作暂停 Agent，并由终端用户决定是否继续。
- 保持 Agent 与终端 UI 解耦，为后续其他 UI 接入保留统一事件接口。
- 不破坏现有 Plan Mode、工具分批执行和流式响应能力。

## 功能需求

- **F1：危险命令硬拦截**
  - 检查 Bash 命令中的全部命令段，包括管道、条件连接和连续命令。
  - 匹配前统一处理大小写、空白和常见 PowerShell/Bash 写法。
  - 硬拦截磁盘格式化、裸设备写入、系统目录递归删除、关机重启、Fork Bomb，以及整个项目的不可逆清理。
  - `git reset --hard`、`git clean -fdx` 和递归删除整个工作区属于硬拦截范围。
  - 硬拦截不能被权限模式、配置规则或 HITL“允许”覆盖。

- **F2：工作区路径沙箱**
  - ReadFile、WriteFile、EditFile、Glob、Grep 只能访问当前工作区。
  - 拒绝绝对路径、包含 `..` 的越界路径以及解析后位于工作区外的路径。
  - 对路径的每一级进行真实路径验证，拒绝符号链接、Windows Junction 和其他重解析点逃逸。
  - 写入前再次验证目标及父目录，降低检查后路径被替换的风险。
  - Bash 固定以工作区为运行目录，并经过危险命令、规则和 HITL 检查；本章不实现操作系统级进程隔离。

- **F3：三层权限规则**
  - 依次加载：
    - 用户级：`%USERPROFILE%/.imiocode/permissions.yaml`
    - 项目级：`<工作区>/.imiocode/permissions.yaml`
    - 本地级：`<工作区>/.imiocode/permissions.local.yaml`
  - 优先级为：用户级 > 项目级 > 本地级。
  - 每条规则包含 `action: allow|ask|deny`、工具名 glob，以及可选的目标 glob。
  - 文件工具以工作区相对路径作为目标；Bash 以规范化命令文本作为目标。
  - 高优先级文件出现匹配后停止向下查找；同一文件内第一条匹配规则生效。
  - 无效规则文件必须明确报错并阻止权限系统以不确定配置运行，不能静默放行。

- **F4：五种权限模式**
  - `LOCKDOWN`：禁止所有工具，规则不能突破。
  - `READ_ONLY`：只允许读取和搜索类工具，写入和命令不能通过规则放行。
  - `ASK`：读取和搜索默认允许，写入和命令默认进入 HITL。
  - `AUTO_EDIT`：读取、搜索和文件修改默认允许，Bash 默认进入 HITL。
  - `FULL_ACCESS`：非硬拦截操作默认允许，但显式 `deny` 或 `ask` 规则仍然生效。
  - 未配置模式时默认使用 `ASK`。

- **F5：统一权限决策**
  - 每次工具执行前按固定顺序经过：危险命令检查、路径沙箱、规则匹配、模式策略、HITL。
  - 输出明确的 `ALLOW`、`ASK` 或 `DENY` 决策，并提供适合展示给用户的原因。
  - 被拒绝的调用不得启动工具进程，也不得产生文件副作用。
  - 权限检查发生在工具分批执行之前；需要确认的操作不能提前进入并发队列。

- **F6：HITL 确认**
  - 需要确认时，Agent 发布权限请求事件并暂停当前工具调用。
  - 终端展示工具名、风险、目标摘要和请求原因，敏感内容继续脱敏。
  - 用户可选择：允许一次、本次会话允许同类操作、拒绝。
  - “本次会话允许同类操作”仅匹配相同工具和等价的规范化目标，不写入规则文件。
  - 用户选择后唤醒等待中的 Agent；拒绝结果作为工具失败回传给模型，使 Agent 可以调整方案。
  - 任务取消或终端关闭时，所有等待中的确认自动按拒绝处理，不能永久阻塞。

- **F7：终端与 Agent 集成**
  - 权限请求和权限结果通过 Agent 事件传递，权限核心不直接依赖终端实现。
  - 确认期间终端显示独立状态，并暂停普通对话输入。
  - Plan Mode 仍只启用读取和搜索工具，同时继续受危险检测、沙箱和显式拒绝规则约束。
  - 多个待确认操作按工具调用顺序串行处理，不并发展示多个确认框。

## 非功能需求

- **N1：安全默认**
  - 无配置时使用 `ASK`。
  - 无法解析规则、无法验证真实路径或权限组件异常时，必须拒绝相关操作。
  - 不允许因为异常、空值或未知工具而降级为自动放行。

- **N2：跨平台**
  - 危险命令检测至少覆盖 Windows PowerShell 与 Linux/macOS Bash。
  - 路径判断同时正确处理 Windows 驱动器、大小写差异、分隔符和重解析点，以及 Unix 符号链接。

- **N3：并发与取消安全**
  - 并行读取工具可以独立完成权限检查。
  - HITL 请求必须有确定顺序，不发生两个终端确认互相抢占输入。
  - Agent 取消、超时或应用退出后，不遗留等待线程和运行中的未授权工具。

- **N4：信息安全**
  - 终端只展示完成决策所需的命令或路径摘要。
  - API Key、环境变量秘密及已支持的敏感内容必须继续脱敏。
  - 拒绝原因可以回传给模型，但不能泄露用户目录结构或规则文件中的无关内容。

- **N5：兼容性**
  - 不改变六个核心工具对模型暴露的名称和参数格式。
  - 不破坏现有 Agent Loop、Plan/Do 切换、工具事件展示、流式响应和对话历史。
  - 现有无权限系统调用方应能通过明确的兼容入口迁移，不能暗中绕过权限检查。

- **N6：性能**
  - 规则文件每次会话加载一次，不在每次工具调用时重复读取磁盘。
  - 普通无需 HITL 的权限判断不执行网络请求，也不启动额外进程。
  - 路径与规则检查的耗时相较工具本身应保持可忽略。

- **N7：可测试性**
  - 危险命令、路径逃逸、规则优先级、五种模式和三种 HITL 回复均可独立测试。
  - 测试不得真实执行系统破坏命令。
  - 端到端验收使用临时工作区和无破坏性的示例命令。

## 不做的事

- 网络访问限制、域名白名单或代理控制。
- CPU、内存、磁盘、进程数量和执行时间等资源配额扩展。
- 权限操作审计日志、历史查询和审计导出。
- Docker、Windows AppContainer、Linux Namespace 等操作系统级 Bash 进程沙箱。
- 解析任意 Shell 脚本全部语义；危险检测聚焦明确黑名单、命令规范化和常见绕过形式。
- HITL 选择后自动修改或生成持久化规则。
- 运行期间热重载权限规则；规则在新会话启动时重新加载。
- 图形化权限管理页面；本章只实现终端确认界面。
- 远程确认、多用户审批或审批超时后的自动允许。
- 按网络来源、用户身份或组织策略下发权限。

## 验收标准

- **AC1（F1）**：提交磁盘格式化、系统根目录递归删除、Fork Bomb、关机重启等代表性命令时，工具不启动，并返回“危险命令已硬拦截”。
- **AC2（F1）**：提交 `git reset --hard`、`git clean -fdx` 或递归删除整个工作区时，无论当前模式或规则如何配置，均无法放行。
- **AC3（F1）**：正常的 `mvn test`、查看 Git 状态和工作区内非整体清理命令不会被危险命令检测器误拦截。
- **AC4（F2）**：六个核心工具使用合法工作区相对路径时可以按权限决策正常执行。
- **AC5（F2）**：绝对路径、`..` 越界路径、指向工作区外的符号链接和 Windows Junction 均被拒绝。
- **AC6（F2）**：写入目标在首次检查后被替换为链接时，执行前复检仍能阻止写入。
- **AC7（F3）**：三层规则都能被加载；同一操作发生冲突时，实际结果符合“用户级 > 项目级 > 本地级”。
- **AC8（F3）**：同一规则文件内多条规则同时匹配时，第一条规则生效。
- **AC9（F3）**：工具名和目标 glob 能分别匹配文件工具与 Bash 命令；无效规则会明确报错且不会放行工具。
- **AC10（F4）**：五种模式分别表现为：`LOCKDOWN` 无工具可执行；`READ_ONLY` 仅读取和搜索可执行；`ASK` 对写入和 Bash 发起确认；`AUTO_EDIT` 自动执行文件修改、对 Bash 发起确认；`FULL_ACCESS` 自动执行没有显式限制且未触发硬拦截的操作。
- **AC11（F4）**：没有权限配置时，实际模式为 `ASK`。
- **AC12（F4）**：`LOCKDOWN`、`READ_ONLY` 的模式上限以及所有硬拦截都不能被 `allow` 规则绕过；`FULL_ACCESS` 仍服从显式 `deny` 和 `ask`。
- **AC13（F5）**：每个工具调用在开始执行前都能观察到权限决策；被拒绝时没有工具进程、文件写入或其他副作用。
- **AC14（F5）**：一批工具同时到达时，未授权工具不会提前进入并行执行；授权后结果仍按原始工具调用顺序回传。
- **AC15（F6）**：需要确认时，终端展示工具、风险、目标摘要和原因，Agent 在用户回复前保持等待。
- **AC16（F6）**：“允许一次”只放行当前调用；“本次会话允许同类操作”可放行后续等价调用；“拒绝”会返回可供模型理解的失败结果。
- **AC17（F6）**：任务取消、超时或终端退出时，待确认请求自动拒绝，应用能够正常结束。
- **AC18（F6）**：多个确认请求按调用顺序逐个展示，不争抢终端输入。
- **AC19（F7）**：权限核心通过事件与终端交互，不直接调用具体终端实现；测试替身可以完成确认流程。
- **AC20（F7）**：Plan Mode、Do Mode、流式文本、工具状态和对话历史在权限系统接入后仍正常工作。
- **AC21（F7）**：Plan Mode 中写入和 Bash 仍不可用，读取与搜索同时受沙箱和显式拒绝规则约束。
- **AC22（整体）**：项目编译成功，新增及既有自动化测试全部通过。
- **AC23（端到端）**：在真实终端中让 Agent 读取文件、请求修改文件并执行安全命令，能够依次观察自动读取、HITL 确认、工具执行和最终回复。
- **AC24（安全端到端）**：在真实终端中请求危险命令和路径逃逸，二者均被拒绝，工作区及外部文件保持不变。
