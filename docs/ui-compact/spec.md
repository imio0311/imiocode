# 精简终端 UI Spec

## 背景

ImioCode 当前会把状态变化、完整 Thinking、工具排队、工具运行、工具完成、Usage、MCP 生命周期和最终回答都追加到终端滚动区。同一个 Agent 迭代会产生多行重复状态，工具参数摘要也包含风险、状态和结果描述，导致真正的回答被大量过程信息淹没。

前一版优化同时缩小了启动信息和对话过程输出。实际使用后，用户希望恢复原有启动面板的品牌感和环境信息密度，但保留已经生效的对话降噪：工具仍收敛为单行结果，默认隐藏不需要阅读的内部状态，同时保留错误、权限确认和调试入口。

## 目标

- 默认使用精简显示，让用户优先看到最终回答和真正有用的工具结果。
- 程序启动时恢复原有响应式完整面板；宽终端显示 Logo、边框、Provider、模型、目录和 Ready，窄终端按现有规则安全降级。
- 默认不输出模型 Thinking 正文、Token Usage、重复状态行和工具中间状态。
- 每个已完成工具最多保留一行安全摘要，失败结果仍清晰可见。
- 启动区保留完整品牌与环境信息，对话区、工具区和输入区继续保持低噪声视觉层级。
- 支持通过 `config.yaml` 选择默认显示模式，并允许会话内即时切换。
- Verbose 模式保留当前详细信息，方便调试 Provider、Agent、MCP 和上下文问题。
- 不改变 Agent、工具、权限、上下文和 MCP 的实际执行语义。

## 功能需求

### F1：UI 显示模式

- 提供 `compact` 与 `verbose` 两种显示模式。
- 未配置时默认使用 `compact`。
- `config.yaml` 可以通过 UI 配置域选择默认模式；非法值必须在启动阶段给出明确配置错误。
- `/verbose` 将当前会话切换为详细模式；`/compact-ui` 将当前会话切回精简模式。
- 两个命令都是本地命令，不发送给模型，不写入对话历史，不改变 Plan/Do 模式。
- 切换成功后只显示一条简短确认，不重绘启动面板或重复历史输出。

### F2：完整启动面板

- 启动面板不受 `compact` 或 `verbose` 详细度影响，始终复用原有响应式完整布局。
- FULL 富终端显示 Logo、边框、产品与版本、Provider、模型、工作目录和 Ready 状态。
- 窄富终端保留边框及环境字段，并按原有终端能力规则省略 Logo；纯文本终端使用无 ANSI 的多行环境摘要。
- 启动面板的每一行继续按终端宽度安全截断，不因恢复完整布局导致越界。
- MCP 例行生命周期事件不逐条打印；连接完成后只展示一条聚合结果，例如连接 Server 数和注册工具数。
- MCP 启动确认、连接失败和配置错误始终可见，不得因精简模式被隐藏。
- Verbose 模式继续显示 MCP 生命周期细节，但与 compact 使用相同的启动面板。

### F3：状态输出降噪

- 精简模式的 `Ready`、`Thinking`、`Streaming`、`Tool waiting`、`Tool running` 状态只更新 UI 内部状态，不向滚动区追加新行。
- 输入区可以展示当前状态，但同一轮状态变化不能产生历史日志堆积。
- 错误、重试、权限等待、手动压缩结果和不可恢复停止原因仍必须输出。
- 自动上下文管理的开始事件隐藏；完成、失败、熔断或大结果落盘只保留一条摘要。
- Verbose 模式保留当前逐状态输出行为。

### F4：Thinking 隐藏

- 精简模式不输出任何 Thinking 文本片段、Thinking 前缀或完成标记。
- Thinking 仍按原协议收集、保存和回传，UI 隐藏不能修改消息历史或 Provider 请求。
- Thinking 中的签名、加密数据和脱敏数据继续保持不可见。
- Verbose 模式继续以当前弱化样式流式展示允许展示的 Thinking 文本。
- 从 compact 切换到 verbose 只影响后续事件，不补打此前隐藏的 Thinking。

### F5：工具执行单行摘要

- 精简模式隐藏工具的 `queued` 和 `running` 事件，只在 `succeeded` 或 `failed` 时输出。
- 同一个工具调用在精简模式最多产生一条完成行，不因 Agent 事件和工具事件双通道重复显示。
- 成功行包含：状态图标、易读工具名称、最关键目标或结果数量，以及可用时的耗时。
- 失败行包含：失败图标、易读工具名称、最关键目标和第一条安全错误摘要。
- 精简行不显示风险等级、内部枚举名称、调用 ID、完整命令输出、写入正文或冗长参数。
- 文件工具优先显示路径；Glob/Grep 优先显示模式与结果数；Bash 显示截断后的命令；未知/MCP 工具显示安全化工具名且隐藏参数。
- 所有摘要继续经过敏感信息脱敏和终端宽度截断。
- Verbose 模式保留 queued、running、succeeded、failed 四态和当前详细摘要。

### F6：回答与输入区

- 精简模式使用短助手标记开始最终回答，避免重复产品全名。
- 流式文本保持实时输出，Markdown、代码块、中文和换行内容不得被压缩或丢失。
- 一轮回答结束后保证恰好一个可读分隔，再进入下一次输入，不与工具行或错误行粘连。
- 输入提示保持简短，并继续支持 Alt+Enter 多行输入、Ctrl+C、`/exit` 与 `/quit`。
- 终端滚动区不重复打印同一条用户输入。
- Verbose 模式保持现有助手前缀、输入面板和状态栏。

### F7：必须可见的信息

- 权限确认对话框、MCP 启动确认、用户选择结果和拒绝原因始终显示。
- 工具失败、配置错误、Provider 错误、Agent 超时、取消、未知工具熔断和可能已产生副作用的提示始终显示。
- `/compact` 的最终压缩报告始终显示；自动压缩失败和熔断始终显示。
- 精简模式可隐藏成功 Usage、正常重试前的内部细节和正常完成原因，但不能隐藏用户需要采取行动的信息。
- 所有错误文本继续使用安全消息，不输出异常栈或敏感正文。

### F8：响应式与纯文本兼容

- 富终端优先使用简洁图标、缩进和颜色建立层级，但不能依赖颜色传达唯一语义。
- 不支持 ANSI 的终端不得输出转义码，并使用可读的 ASCII 标记替代图标。
- 所有启动行、工具摘要、模式提示和错误行均不得超过当前终端宽度。
- 20、40、60、100 列宽度下均保持可输入、可阅读；窄终端允许进一步省略非必要文字。
- Windows PowerShell、CMD、Linux/macOS 终端的换行和 Unicode 行为保持兼容。

### F9：配置与帮助文档

- `config.example.yaml` 包含默认精简 UI 的配置示例。
- 统一配置文档说明 `compact`、`verbose`、`/verbose` 与 `/compact-ui`。
- 启动提示或帮助信息能够让用户发现模式切换命令，但不能每轮重复展示。
- 旧 `config.yaml` 不增加 UI 配置时自动使用精简模式并正常启动。

## 非功能需求

### N1：安全

- 显示模式只控制可见性，不得改变权限决策、工具调用、对话历史、上下文压缩或 MCP 生命周期。
- compact 与 verbose 均使用同一脱敏器和安全错误来源。
- 被隐藏的 Thinking、Usage 和工具过程不得通过其他摘要字段意外泄露。

### N2：性能

- 精简过滤在终端展示层完成，不增加 LLM 请求、工具执行或磁盘 I/O。
- 恢复启动面板只复用现有布局计算，不增加网络请求、配置读取或持久状态。
- 事件过滤和摘要格式化保持常数级额外状态，不缓存完整 Thinking 或工具输出用于 UI。
- 流式回答仍逐片段刷新，不因精简模式增加明显延迟。

### N3：兼容性

- 保持现有 `TerminalUi` 调用方、AgentEvent、ToolExecutionEvent 和三家 Provider 协议行为。
- 保持 FULL / COMPACT / PLAIN 三类终端能力的响应式降级规则和纯文本终端无 ANSI 行为。
- 保持 Plan/Do、权限 HITL、MCP、自动压缩、手动 `/compact` 和退出命令行为。
- dumb terminal 与测试中的内存终端继续可用。

### N4：可测试性

- compact 与 verbose 的显示差异可以用同一组事件序列稳定断言。
- 工具事件去重、Thinking 隐藏、状态不落滚动区、模式切换和宽度截断均有独立测试。
- 至少用真实 shaded JAR 完成一次精简模式对话或可控事件端到端场景。
- 原有测试保持 0 failures、0 errors；旧详细 UI 测试应明确运行在 verbose 模式。

## 不做的事

- 不新增 `startup-style` 等启动样式配置；启动面板固定复用原响应式布局。
- 不恢复 compact 对话过程中的输入边框、状态栏、Thinking、Usage 或工具 queued/running 日志。
- 不在 `/verbose` 或 `/compact-ui` 切换时重绘启动面板。
- 不重写为全屏 TUI，不引入鼠标、窗口分栏、弹窗框架或持久任务列表。
- 不实现历史记录搜索、会话选择器或截图三所示的历史会话列表页面。
- 不对模型最终回答做摘要、截断或二次改写；“精简”只针对 UI 过程噪声。
- 不改变 System Prompt 来要求模型缩短回答，本次只优化终端展示。
- 不在终端侧生成 Thinking 摘要，也不调用额外 LLM 压缩 Thinking。
- 不隐藏权限确认、危险操作、失败和副作用警告。
- 不实现运行时主题编辑、颜色配置或自定义图标包。

## 验收标准

- AC1（F1）：未配置 UI 时默认为 compact；合法配置生效，非法配置阻止启动。
- AC2（F1）：`/verbose` 与 `/compact-ui` 即时切换后续输出，命令不进入模型请求或历史。
- AC3（F2）：compact 与 verbose 在同一终端能力下生成相同启动面板；FULL 模式可观察到 Logo、边框、版本、Provider、模型、目录和 Ready。
- AC4（F2）：MCP 确认、连接失败和配置错误在 compact 下仍可见。
- AC5（F3）：一轮 `Ready → Thinking → Streaming → Tool waiting → Tool running → Ready` 不在 compact 滚动区产生状态日志。
- AC6（F3）：verbose 对同一状态序列继续输出详细状态。
- AC7（F4）：compact 收到多个 Thinking 片段时输出中找不到 Thinking 正文、前缀或敏感元数据。
- AC8（F4）：切换 verbose 后，新 Thinking 片段按原样式展示，先前片段不会补打。
- AC9（F5）：工具 queued、running、succeeded 序列在 compact 中只生成一条成功摘要。
- AC10（F5）：失败工具在 compact 中只生成一条包含安全首行错误的失败摘要。
- AC11（F5）：六个内置工具和未知/MCP 工具都有符合规则的单行摘要，且不泄露正文、完整输出或敏感参数。
- AC12（F5、F8）：长命令、中文路径和长 MCP 名称经过脱敏与列宽截断，所有行不越界。
- AC13（F6）：最终回答仍逐片段完整输出，代码块和多行文本不丢失，下一输入提示不粘连。
- AC14（F6）：Alt+Enter、Ctrl+C、退出、Plan/Do 和 `/compact` 命令继续工作。
- AC15（F7）：权限确认、拒绝、工具失败、Provider 错误、Agent 停止和副作用警告在 compact 下均可见。
- AC16（F7）：Usage、正常 Thinking、工具中间态和普通 MCP 生命周期在 compact 下不可见。
- AC17（F8）：富终端与 dumb terminal 都能区分回答、成功、失败和确认，dumb 模式无 ANSI。
- AC18（F2、F8）：20、40、60、100 列下恢复后的启动面板及工具、模式和错误行都不超过终端宽度；纯文本启动面板不含 ANSI。
- AC19（F9）：示例配置和文档包含 UI 模式及切换命令，旧配置无需修改即可启动。
- AC20（N1-N3）：两个显示模式下 Agent、权限、MCP、上下文和 Provider 请求回归测试行为一致。
- AC21（N4）：新增聚焦测试与项目全量测试 0 failures、0 errors，真实进程可观察到完整启动面板及精简对话输出，或如实记录环境阻塞。
- AC22（F1、F3-F7）：恢复启动面板后，compact 仍隐藏 Thinking、Usage、状态日志和工具中间态，并继续显示单行工具结果、完整回答、权限与错误。
