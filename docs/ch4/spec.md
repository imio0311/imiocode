# ImioCode 第四章：Agent Loop Spec

## 背景

ImioCode 已具备流式模型对话、结构化 Thinking、六个核心工具及单批工具执行能力。当前每个用户任务最多执行一批工具；模型收到工具结果后若再次请求工具，系统会停止。因此，它还不能根据前一步结果继续调查、修改、验证和修正。

本章引入 Agent Loop，让模型在一个用户任务中反复进行“思考 → 调用工具 → 获取结果 → 决定下一步”，直到生成最终回答或触发明确的停止条件。

## 目标

- 支持模型自主完成多步代码任务。
- 将 Agent 执行过程通过统一事件流暴露，与终端 UI 解耦。
- 实时显示每轮模型文本、Thinking、工具执行和停止状态。
- 并发执行连续的安全只读工具，并对写入及命令工具保持顺序屏障。
- 提供持续生效的 Plan Mode，只允许调查和输出计划。
- 对循环轮数、总时长和安全工具并发数设置可配置上限。
- 成功时原子保存完整 Agent 轨迹，失败时不污染正式历史。
- 保持三家模型服务和现有六个工具行为一致。

## 功能需求

- F1：系统应提供独立的 Agent 执行能力，接收用户任务、已提交历史、当前模式和一次性提醒，驱动完整任务。
- F2：每次循环都应把当前任务的完整临时轨迹发送给模型，包括此前的助手响应、工具调用和工具结果。
- F3：模型返回工具调用时，系统应执行该批工具、追加结果并自动进入下一轮模型请求。
- F4：模型返回不包含工具调用的完整响应时，应将其视为最终回答并正常结束任务。
- F5：普通工具失败不得直接终止循环；失败结果应回传模型，由模型决定重试、换工具或结束。
- F6：流式收集过程应实时透传文本、Thinking、工具调用和 Usage 事件，同时积攒完整结构化响应供循环使用。
- F7：流未正常结束、工具参数不完整或响应结构无效时，不得使用半成品响应继续循环。
- F8：Agent 应具有五种停止条件：得到最终回答、达到最大循环轮数、达到任务总超时、发生无法在本轮继续的错误、用户中断或程序关闭。
- F9：达到轮数或超时时，不得再请求模型或启动新工具，并应给出可区分的停止原因。
- F10：用户中断时，应取消活动模型请求、活动工具及并发工具任务，并阻止后续循环。
- F11：每轮循环开始、模型流事件、工具执行、模式变化、任务完成、任务停止和任务失败，都应通过统一 Agent 事件流发布。
- F12：Agent 事件应包含足够的轮次、调用和停止原因信息，使 UI 无需读取 Agent 内部状态。
- F13：Agent 核心不得直接调用终端展示逻辑；终端只能消费 Agent 事件。
- F14：连续的 ReadFile、Glob 和 Grep 调用应组成安全批次，并在配置的并发上限内执行。
- F15：WriteFile、EditFile 和 Bash 应作为顺序屏障：等待此前安全批次完成，再按模型顺序逐个执行。
- F16：屏障后的连续安全工具可组成新的并发批次。
- F17：无论实际完成顺序如何，工具结果、事件关联和模型回传顺序都必须与原始工具调用顺序一致。
- F18：安全工具并发执行时，单个失败不得取消同批其他工具；每个调用都应得到独立结果。
- F19：`/plan` 应切换到持续生效的规划模式，命令本身不请求模型且不进入会话历史。
- F20：规划模式只向模型公开 ReadFile、Glob 和 Grep，并明确要求模型只调查项目、输出实施计划，不执行修改。
- F21：规划模式中的多轮只读工具调用仍使用完整 Agent Loop，并受相同轮数、超时和中断限制。
- F22：`/do` 应恢复正常模式和全部六个工具；命令本身不请求模型且不进入历史。
- F23：`/do` 不自动执行上一次计划，用户必须明确发送新的执行任务。
- F24：当前模式应持续到用户显式切换或程序退出。
- F25：最大循环轮数默认 20，单任务总超时默认 10 分钟，安全工具最大并发数默认 4。
- F26：三项运行预算应支持通过 YAML 和环境变量分别覆盖；非法配置应阻止启动并指出配置项。
- F27：一次性系统提醒应在同一 Agent 任务的每次模型请求中保持一致，任务结束后被消费，且不进入正式历史。
- F28：成功得到最终回答后，应原子提交用户消息、所有中间助手响应、所有工具结果和最终回答。
- F29：轮数耗尽、超时、错误或中断时，未完成轨迹不得进入正式历史。
- F30：已经执行的文件修改或命令副作用不自动回滚；异常结束时必须明确说明可能存在已执行副作用。
- F31：同一 Agent Loop 应适用于 OpenAI、Anthropic 和 DeepSeek，不在 Agent 层加入厂商分支。
- F32：原有纯文本聊天、Thinking、Usage、工具安全边界、敏感信息脱敏和退出命令应继续正常工作。

## 非功能需求

- N1：Agent 循环、事件模型、工具调度和会话历史应保持模块化，可分别测试。
- N2：安全工具并发必须有固定上限，不得为每个调用创建无界线程或任务。
- N3：任何两个写入或命令工具都不得并发；安全工具也不得跨越顺序屏障执行。
- N4：并发工具的完成时间可以不同，但事件关联、结果列表和模型上下文必须保持确定性。
- N5：循环次数、任务时长和并发数都必须在启动时完成校验，运行中不得出现零值、负值或无界配置。
- N6：超时、中断和关闭后不得遗留模型请求、工具进程、并发任务或执行线程。
- N7：取消操作应幂等；重复中断或关闭不得重复提交历史或重复发布完成事件。
- N8：每个任务只能产生一个最终状态：完成、停止或失败，三者互斥。
- N9：Agent 事件必须按实际生命周期发布，不能在工具真正完成前发布成功，也不能为异常流发布正常完成。
- N10：事件流和终端输出不得泄露 API Key、认证头、Thinking 签名、encrypted content 或受保护文件内容。
- N11：所有文本、工具参数、工具结果、计划和事件内容统一保持 UTF-8 与 Unicode 正确性。
- N12：本章不自动重试模型请求；网络、限流或服务错误会结束当前任务，并保留是否可由用户重新发起的错误元信息。
- N13：现有工具超时、输出截断、工作区限制、敏感路径保护和脱敏规则继续生效。
- N14：Plan Mode 的工具可见性必须由每次任务的模式快照决定，不得因并发执行发生中途变化。
- N15：旧配置不增加 Agent 字段时仍能启动，并使用 20 轮、600 秒、4 并发的默认值。
- N16：现有调用方应能迁移到 Agent 事件而不要求修改三家 Provider 的协议实现。
- N17：自动化测试不得依赖真实 API Key、外部模型服务或用户工作区，应使用临时目录和本地模拟服务。
- N18：项目应在 Java 21 下干净编译、测试和打包，并保持 Ch2、Ch3 全部现有测试通过。
- N19：应提供真实进程端到端测试，验证多轮工具循环、Plan Mode、并发屏障、中断和正常退出。
- N20：若当前环境缺少 tmux，应记录明确阻塞证据，不得将 tmux 人工验收标记为通过。

## 不做的事

- 不实现权限系统或危险工具执行前确认。
- 不实现上下文压缩、摘要或 Token 窗口自动裁剪。
- 不实现用户确认机制或工具调用审批界面。
- 不自动执行 Plan Mode 生成的计划。
- 不自动重试模型请求、工具调用或失败步骤。
- 不自动回滚文件修改、命令副作用或部分完成的工作。
- 不增加新的核心工具，也不改变六个现有工具的参数契约。
- 不实现跨用户任务的后台 Agent；每次用户输入对应一个前台任务。
- 不支持暂停后跨进程恢复 Agent 轨迹。
- 不实现多个 Agent 或子 Agent 协作。
- 不实现运行时插件发现、MCP 或 Skill 系统。
- 不实现自动 Git 提交、推送或创建 Pull Request。
- 不允许不安全工具并发执行。
- 不在 Agent 层实现厂商特有协议逻辑。
- 不把未完成 Agent 轨迹写入正式会话历史。

## 验收标准

- AC1：模拟模型连续返回至少两批工具调用后再返回文本，系统自动完成所有循环并只向用户请求一次输入。
- AC2：模型响应不包含工具调用时，Agent 立即以最终回答正常结束，不再发起模型请求。
- AC3：最终回答、最大轮数、任务超时、错误、用户中断五种条件都能产生可区分的最终状态，且每个任务只产生一个最终状态。
- AC4：流式文本和 Thinking 在模型生成期间实时可见，同时循环能获得包含文本、Thinking、工具调用和 Usage 的完整结构化响应。
- AC5：模型流截断、工具 JSON 不完整或缺少完成事件时，Agent 不执行半成品工具，也不继续下一轮。
- AC6：某个工具执行失败时，失败结果进入下一轮模型上下文；同批及后续步骤仍可继续，直到模型调整策略或结束。
- AC7：连续 ReadFile、Glob、Grep 的执行时间存在重叠，且同时运行数量不超过配置上限。
- AC8：WriteFile、EditFile、Bash 与其前后工具之间形成顺序屏障；任意两个不安全工具都不存在执行时间重叠。
- AC9：并发工具即使乱序完成，事件关联、结果回传和下一轮模型请求中的排列仍与原始调用顺序一致。
- AC10：在模型流、安全工具批次或 Bash 执行期间中断，活动工作立即停止，不再启动工具或请求模型，也不提交历史。
- AC11：监听统一 Agent 事件即可完整还原任务开始、每轮模型响应、工具批次、工具状态、模式和最终结果；Agent 核心不依赖终端。
- AC12：输入 `/plan` 后不产生模型请求且不进入历史；后续任务只公开 ReadFile、Glob、Grep，并最终输出计划。
- AC13：Plan Mode 中即使模型请求 WriteFile、EditFile 或 Bash，这些工具也不会执行。
- AC14：输入 `/do` 后不产生模型请求、不自动执行旧计划；下一任务恢复全部六个工具。
- AC15：未配置 Agent 字段时使用 20 轮、600 秒和 4 并发；YAML 与环境变量可分别覆盖；非法值安全阻止启动。
- AC16：同一任务中的每次模型请求携带相同的一次性提醒；任务完成、停止或失败后下一任务不再携带，提醒不进入历史。
- AC17：成功任务一次性提交用户消息、全部中间助手消息、全部工具结果和最终回答，顺序与执行轨迹一致。
- AC18：轮数耗尽、超时、错误和中断均不提交未完成轨迹；若已有写入或命令执行，终端明确说明副作用可能存在。
- AC19：相同多步场景使用 OpenAI、Anthropic 和 DeepSeek 模拟协议时，Agent 循环、事件和工具结果行为一致。
- AC20：纯文本聊天、Thinking、Usage、六个工具、工作区保护、敏感信息脱敏、Unicode 和退出命令全部回归通过。
- AC21：真实 Java 进程能完成“读取代码 → 修改文件 → 运行验证命令 → 根据结果生成最终回答”的多步场景，并能正常退出。
- AC22：Java 21 干净编译、全部自动化测试和可执行 JAR 打包成功；tmux 可用时完成真实终端验收，不可用时记录环境阻塞。
