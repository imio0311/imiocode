# Test 工作流

测试范围：$ARGUMENTS

1. 检查项目构建文件和现有测试目录，选择最小但充分的测试命令。
2. 先运行与当前改动最相关的测试，再按风险决定是否扩大到完整测试。
3. 保留命令、退出码和关键失败输出；不要把警告误报为失败。
4. 测试失败时定位首个根因，区分代码缺陷、环境缺失和不稳定测试。
5. 用户要求修复时再修改代码；仅要求测试时不要擅自改动。
6. 最终简洁报告通过数、失败数、耗时、失败原因和建议下一步。
